# Prepared checkpoint browser falsification

This probe is source only and unexecuted. It starts no Metro server, installs nothing, and requires
an explicit owned loopback URL, existing browser registry, exact dirty-source receipt, new output
directory, and campaign-approved replay/RSS-growth budgets. It launches and closes only its own
Chromium process/profile. A failed probe preserves result.json and prior exports; no retry hides it.

The actual app reopens v3 fixtures through Pictures and the production parser. Instrumentation
observes react-native-svg's real browser Canvas PNG capture and actual SVG Image load events.
Transparent captures from the real checkpoint path are compared before/after lossless PNG/Image
replacement. A protected Crayon/Magic/solid region remains untouched by disjoint later operations;
any pixel drift fails. A separate erased-blue then fresh-red case detects erasing future paint. The
legal 1000-op case performs chronological prefix checkpoints and real hidden export replay.
Application DOM depth and image count are observed, while only two PNG strings remain retained by
instrumentation during depth work. The protected fixture corner stays transparent, so the Canvas
corner-alpha tag selects ink captures rather than retaining the final opaque paper PNG. Actual full
PNG alpha is decoded again before comparison; this tag is not the product blank detector.
Process-tree RSS includes graphics/cache growth but may double count shared pages; it is browser
evidence, not native memory qualification.

The missing-callback control suppresses one actual web SVG image-load callback, waits for production
capture timeout, invokes that captured callback twice after settlement, and checks live artwork plus
real saved v3 data/rainbow retention. It does not prove native callback cancellation or native image
cache behavior. Incoming checkpoint-load timeout, stale React onLoad dispatch, rejected decoding,
Undo/reopen after depth, and native memory/latency require their own controls before acceptance.

The command is intentionally not run during source preparation:

```sh
PLAYWRIGHT_BROWSERS_PATH=<existing-absolute-registry> node tools/migration/probes/native-eraser/checkpoint-browser.mjs --phase=<small-or-depth> --url=http://127.0.0.1:<owned-port> --browser-registry=<existing-absolute-registry> --source-receipt=<exact-current-source-receipt> --output=<new-private-directory> --replay-budget-ms=<approved-budget> --rss-growth-budget-mib=<approved-budget>
```

First qualify source/type/transform, then run phase=small for roundtrip/load/failure controls, then
phase=depth for legal operation replay before spending a native owner implementation. If legal-depth
replay times out or exceeds the resource budget, that failure stays in this same eraser unit; no cap
reduction or renamed follow-up. Native PNG alpha observation remains deferred until the production
pipeline passes. No sibling feature, source, framework or native acceptance follows from this
prepared script.
