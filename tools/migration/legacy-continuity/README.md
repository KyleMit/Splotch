## Commands and raw capture

methods require the run's 32-hex nonce in the actual fixed Preferences ownership marker. Page

Android's `android-command` attaches to an already qualified, owned app PID. Its lease binds:

## Persistence cuts and controls

Writer acknowledgement is a memory stage. Within the preregistered 5,000 ms observation deadline,
capture the independent two Android shared_prefs XML files via run-as, their existence/mode/full
bytes, parsed types and in-process alias state. The observer's `disk` command preserves complete XML
bytes plus digest and selected typed rows. Capture raw XML separately even when parsing rejects. On
iOS capture the actual container Preferences plist/cfprefsd boundary and source relaunch read; do
not kill cfprefsd or access arbitrary host defaults. Then terminate only the owned app process and
relaunch the **source** for raw readback before any reader reinstall. Record every failed stage
separately. Do not reseed or hydrate before that readback.

After qualified in-place reader installation, capture raw state first; only then `vault-read`,
`preferences`, actual `hydrate` or one fresh-document `parse`. A second parse in the same document
refuses because the actual settings module caches initialization. Raw keys, types, bytes and actual
parser behavior remain separate claims.

## Tool ownership and retirement

Any source revision, owner literal/registration, tool/template, graph, generated configuration,
artifact, signing/profile, runtime or transport change invalidates the relevant prior receipt.
Update the finite owner/command inputs and review changed boundaries before trust execution. Stop on
incomplete provenance, unintended negative failures or a material open finding. Do not repeat a
complete unchanged probe solely because another integrator owns it.

Retire this fixture owner only after the destination's reviewed same-ID raw reads, ordered
transactions, supported-source/signed-channel and applicable pack/job/held-picture gates transfer
the obligations. Preserve tested revisions, complete receipts and original review provenance first.
The host guard suite demonstrates refusals and restored controls for the tools; it cannot prove
native crypto, IndexedDB execution, installed graph or upgrade behavior.
