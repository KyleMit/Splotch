## Commands and raw capture

Host commands use an owned stable Node gate. Its actual OS identity is qualified before target start
and re-proved before every signal. Target PID/invocation/exit receipts remain distinct from gate OS
identity. Natural gate exit is checked for surviving group members before output settlement;
unresolved ownership refuses signals. Every group probe records present, absent or indeterminate;
only ESRCH establishes absence. A denied probe preserves the primary target failure alongside the
ownership refusal and still finalizes closed output bytes and command receipts. The orphan controls
independently inventory actual process-group membership to observe natural disappearance; a failed
inventory never authorizes cleanup. Channel EOF and actual destination closure are separate. On
finalization failure the owner destroys its write destinations and waits for actual close. A
still-unclosed file is retained as an unsettled path without a hash or completeness claim; the
command fails. Already closed files preserve their observed bytes and digests.

Host receipt outputs use a new owned-name directory beneath the canonical platform temporary root or
canonical `/tmp`; realpath resolution rejects a parent symlink escaping both roots. Source
materialization keeps its separate disposable fixture-root policy.

Both routes expose one finite command vocabulary. They never seed automatically. Native mutation
methods require the run's 32-hex nonce in the actual fixed Preferences ownership marker. Page
mutations also require the unchanged unrelated owned sentinel and a completed raw snapshot. Raw
native maps must contain every exact selected key/account. Missing or unavailable observations
refuse seeding; nullable app getters cannot prove absence.

Core seed values are non-default and valid: sound false, volume 37, theme dark, released advanced
controls/main tool drawer false, coloring false and AI true. Actual source storage/secure writers
write these values and nonce-specific dummy secrets. AI true remains inert on this isolated route.
The reader cannot seed. The old advanced-controls key remains separately visible because current
toolDrawer is a different owner. Cleanup removes only the selected core keys and two logical
secrets, cleans their Android orphan rows, and retains held records, legacy rows and sentinels.

## Persistence cuts and controls

Writer acknowledgement is a memory stage. Within the preregistered 5,000 ms observation deadline,
capture the independent two Android shared_prefs XML files via run-as, their existence/mode/full
bytes, parsed types and in-process alias state. The observer's `disk` command preserves complete XML

command captures an observation; it does not enforce the separate writer-to-observation deadline.
Capture raw XML separately even when parsing rejects. On iOS capture the actual container
Preferences plist/cfprefsd boundary and source relaunch read; do not kill cfprefsd or access
arbitrary host defaults. Then terminate only the owned app process and relaunch the **source** for
raw readback before any reader reinstall. Record every failed stage separately. Do not reseed or
hydrate before that readback.

After qualified in-place reader installation, capture raw state first; only then `vault-read`,
`preferences`, actual `hydrate` or one fresh-document `parse`. A second parse in the same document
refuses because the actual settings module caches initialization. Raw keys, types, bytes and actual

## Tool ownership and retirement

Any source revision, owner literal/registration, tool/template, graph, generated configuration,
artifact, signing/profile, runtime or transport change invalidates the relevant prior receipt.
Update the finite owner/command inputs and review changed boundaries before trust execution. Stop on
incomplete provenance, unintended negative failures or a material open finding. Do not repeat a
complete unchanged probe solely because another integrator owns it.

Retire this fixture owner only after the destination's reviewed same-ID raw reads, ordered
transactions, supported-source/signed-channel and applicable pack/job/held-picture gates transfer
the obligations. Preserve tested revisions, complete receipts and original review provenance first.
The host guard suite demonstrates refusals and restored controls for the tools; it cannot prove
native crypto, IndexedDB execution, installed graph or upgrade behavior.
