# reconcile-code-map — design notes

Built for issue 2326 in two phases on 2026-09-25: first the counting rules were scripted and the map
regenerated by hand, then the skill was written from the log of that run. This file is that log.

## Why a generator first

Before `tools/code-map/`, the counting rules existed only as prose in the map's Method section, and
each refresh re-applied them by hand, with no file lists kept. Between the 2026-08-19 snapshot and
the refresh, 2,751 commits landed and nothing regenerated it. A script fixes the reproducibility
half of that. The skill exists for the half a script cannot do: deciding what a new directory *is*,
whether a fallback placement is right, and what the numbers mean.

## Calibration against the old snapshot

The rules were tuned by running them against d3dad50b5404, the commit the 2026-08-19 map described,
and comparing counts until they matched. With the final rules, every area and exclusion count there
matches the old tables exactly, except for two deliberate Method changes:

* The map no longer counts itself (211 lines, 1 file, in `docs`). Counting it would make the totals
  depend on the rendering they produce.
* JSON under any `fixtures/` directory is measurement data (`tools/perf/fixtures/*.seed.json`, 23
  lines, 1 file). At HEAD this rule moves about 15k lines of recorded device frame-stamp captures
  out of `tools/perf`, where they would otherwise have been counted as code.

The `web/src` domain split could not be reproduced exactly, because the original assigned files by
hand and kept no list. The rules land within a few percent on most domains. The larger gaps are
Design system (7.1k vs 6.7k) and Routes / app shell (5.5k vs 5.8k), from `app.css`, `tokens.css`,
and the icon-name declarations sitting on those boundaries.

## Judgment calls the rules encode

* **`lib/state/*` stays in App state** unless one feature clearly owns the module: AI, the canvas,
  coloring, install, settings and the parental gate, colors, and save-folder/save-failure. The first
  draft moved state to its feature domain wholesale and shrank App state from 1.7k to 131 lines,
  which contradicted the original's 17-file App state row.
* **Nested `.ruler/AGENTS.md` sources count in the area they describe**, as an `instruction source`
  sub-bucket, matching the original's per-area rows. Only the root `.ruler/` is its own area.
* **Tests follow their subject by filename stem** (`storage.restore.integration.test.ts` →
  `storage`), and `*TestHarness.ts` follows the module it drives. Route files (`+page.svelte`) and
  files at the `web/src` root keep their full names, because the stem alone would merge `app.css`
  with `app.html`.
* **`verify-key` is an AI route.** It validates the OpenAI key, so it sits with the generation
  routes, while `verify-access-code` stays in Server / API backend.
* **Evidence packages are split by extension, not by directory.** Their scripts and Markdown are
  authored and measured; JSON, JSONL, TSV, `.out`, logs, and gzip are captured and excluded. The
  alternative — excluding `docs/scratchpad/**` wholesale — would have hidden 27k lines of real
  written analysis.
* **SVG is split by origin.** Hand-authored icons and the `store-drawings` authoring samples stay
  measured, as they were at the old snapshot. Coloring outlines, traced corpora, and vectorizer
  output are drawings and got a new "Vector art" class — 13 SVGs under `tools/model-eval/samples`
  alone ran from 3k to 11k lines each.

## Prose judgments that could not be scripted

* Which growth to call out, and the one-line cause of each (for example, "`/dev` harnesses and
  `lib/boot`" for the Routes / app shell doubling). A script can rank deltas; it cannot name the
  cause.
* Whether a new top-level directory is authored or captured. `perf-profiles/` is both.
* Whether a fallback placement is right. The 2026-09-25 run left most fallback-caught new files
  where they landed and gave only `state/saveFailure` a precise rule.

## Why the map is not drift-checked in CI

The issue asked whether the map could be regenerated in CI with a drift check. It can be generated
deterministically, but a gate would fail nearly every pull request: almost any change moves some
count. The alternatives were a CI job that commits the map back to `main` (it needs a write token
and creates commits nobody reviewed, the same objection `tools/flaky-digest` recorded) or a weekly
schedule (the numbers would stay fresh but the prose would not). The CI guard is the rule-coverage
test, which fails only when a path matches no area — the one change that needs a human decision.

## Open questions

* The fallback rules keep the test green when a new `web/src` file appears, at the cost of silent
  misplacement until the next reconcile. If misplacements pile up, consider a fallback report in the
  generator's output rather than failing the build.
* The domain list is the original's 19. Nothing yet decides when a domain should split or merge; the
  first candidate is Routes / app shell, whose `/dev` harnesses are now about a third of it.
