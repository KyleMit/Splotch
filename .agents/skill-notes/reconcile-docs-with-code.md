# reconcile-docs-with-code — design notes

Built for issue 2325 in two phases on 2026-09-25: first a scanner was written and every real hit
fixed by hand, then the skill was written from the log of that run. This file is that log.

## Phase 1 result

The issue's surface scan counted 58 backticked paths pointing at missing files. The first scanner
draft, reading every inline code span with a slash or a file extension, reported 690 unresolved
references (574 paths, 100 identifiers, 16 npm scripts). After the rules below, the gating count was
3, all real, and all fixed:

* `docs/DEPENDENCIES.md` cited `web/src/lib/server/ai/gemini.ts` and `geminiSafety.ts` as the
  `@google/genai` users. Both went with the Gemini → OpenAI swap (ADR-0113); the SDK now lives only
  in the asset-gen and model-eval tooling, as a dev dependency.
* `tools/asset-gen/README.md` listed `geminiSafety.ts` among the sanctioned `web/src` imports. The
  classifier moved to `tools/asset-gen/lib/gemini-response.ts`; the list is four modules now, and
  `tools/asset-gen/.ruler/AGENTS.md` said "five" too.
* `tools/perf/split-capture/README.md` pointed at `../../ios/…`, one level too far up.

The Gemini swap also left `web/src/.ruler/AGENTS.md` saying the `@google/genai` SDK is only touched
inside `lib/server/ai/`. No path broke there, so the scanner could not see it; it was found by
following the swap by hand, which is why step 4 of the skill exists.

Of the issue's three named examples, only `gemini.ts` was a real hit.
`tools/android/android-setup.mjs` is a deliberate counter-example in the tools naming rule, and
`ios/capture-webkit-frames.mjs` in `tools/perf/README.md` resolves relative to that README. The
issue's `npm run` examples (`gen:coloring-punch`, `coloring-fills`) are in an ADR and in the
asset-gen README, where the second is a package alias and resolves.

## False-positive classes the scanner had to learn

In the order they surfaced, with roughly how many hits each removed:

* **Generated copies** (hundreds): `.claude/skills/`, `.agents/skills/`, and every file whose first
  line is Ruler's `<!-- Source: …` or `<!-- Generated by Ruler -->` marker. Scanning their `.ruler/`
  source alone reports each finding once. The registered direct-provider packages have no source, so
  they stay in.
* **Skill notes and `NOTES.md` design logs** (about 20): they narrate proposed and retired designs
  by name — "a `tools/worktrees/` capability", "the dropped `.issue-stack/run.json`". The dead path
  is the point. `README.md` in `.ruler/skill-notes/` calls these notes design history, which settled
  it.
* **Single filenames** (about 400): `findings.json`, `auth.json`, `.ts`. A bare filename names a
  runtime artifact or an extension as often as a tracked file, and resolving it by basename anywhere
  in the tree was so lenient that it caught nothing.
* **Path tails** (about 100): docs about `web/src` write `lib/drawing/engine.ts` or
  `state/appearance.svelte.ts`. Any two-or-more-segment tail of a tracked path resolves. Candidate
  bases alone (the doc's folder and each ancestor) did not cover these, because the docs live in
  `docs/`, not beside the code.
* **Gitignored paths** (about 15): `web/build`, `.claude/worktrees`, `web/.env.local`. The repo's
  own ignore rules decide, through `git check-ignore --no-index`. A directory-only pattern
  (`build/`) does not match a nonexistent bare path, so each candidate is also probed with a child.
* **Placeholders** (a few): `NNNN`, `YYYY`, and `-N.` (`pencil-N.mp3`).
* **Navigation** (2): `../../..` in a `cd` instruction.
* **Extensionless spans under an inner folder name** (about 20, introduced and then removed): once
  any tracked folder name could anchor a path, `actions/checkout`, `claude/<branch>`,
  `splotch/keyframe-curves` (a lint rule), and coloring page ids such as `nature/ant-wide` all
  matched. An unanchored span now needs a top-level folder (of the repo or of `web/`), or a file
  extension plus some tracked folder name.
* **Paths on another machine** (4): `Library/Preferences/…plist` on the iPad, `packet/diff.patch` in
  a session folder, capture-folder `actions.json` paths. They start at a name the repo does not
  have.
* **npm namespaces and flags** (16, every script hit): `npm run perf:*` (the glob is cut off by the
  match) and `npm run --silent x`. No real missing npm script remained after these.

Nineteen references stay in `ALLOWED_REFERENCES`, one per doc and reference, each with a reason:
counter-examples, retired files a doc records (`docs/BACKLOG.md`), files a procedure tells the
reader to create, import specifiers quoted relative to another file, and pilot catalog keys.

## Identifiers are advisory, not gated

The identifier pass (call-shaped, camelCase, PascalCase with an inner capital, or SCREAMING_SNAKE
spans, checked against every word in tracked source) reported 79 after the doc exclusions. One was a
stale repo symbol: `repaintAll` in `docs/PROFILING.md`, removed by the single-source engine work;
the tiled renderer's full repaint is `repaintTiledRenderer`. The rest were platform constants, CDP
events, env vars, agent tool names, third-party API fields, evidence-JSON fields, illustrative
examples, and counter-examples. A 1-in-79 hit rate cannot gate CI, and no rule tells
`LANDSCAPE_LEFT` from a renamed constant without reading the sentence. So identifiers print under
`--identifiers` and never fail the run.

## CI gate instead of most of the skill

The path and script half runs in about two seconds with zero findings and needs no judgment, so it
gates CI the way `check:skill-refs` does: `tools/tests/doc-references.test.mjs` asserts the whole
repo is clean, inside `npm run test:tools`. That turns the backlog problem into a per-PR problem:
the PR that renames a file fixes the docs naming it. The skill covers only what the gate cannot
decide.

The allowlist has its own drift check: an entry that no longer matches a live unresolved reference
fails the gate, so a doc that gets fixed cannot leave an exemption behind to hide the next miss.

## Review round 1 (rival, PR 2336)

The Codex review reproduced three holes the first draft's own suite missed, all fixed:

* **Links were read like prose.** A Markdown link target went through the prose rules, so a
  single-file link (`[x](README.md)`) was never checked, and a relative link was retried against
  every ancestor folder — `./README.md` in `tools/vectorize/docs/` passed on `tools/vectorize/`'s
  README, though every reader following it would hit a 404. Links are now their own kind: any
  segment count, resolved once from where the doc renders. A Ruler orientation source renders in the
  `CLAUDE.md` beside its `.ruler/` folder, so its links resolve from there; a skill source's copies
  sit at the same depth as the source, so its own folder serves. Link syntax quoted inside a code
  span is skipped. Zero new hits after the change.
* **Path tails were accepted when shared.** `docs/pipeline.md` resolved on two different files.
  Tails now map to the one path they end, and a shared tail resolves nothing.
* **`tools/asset-gen/docs/` exclusion.** The review argued these "in force" records are living.
  Including them surfaced 7 hits: 6 were rename and migration narrative ("`twin-src/` →
  `fill-src/`", "since retired") and one was the present-tense shared-module contract in
  `architecture.md`, still listing `geminiSafety.ts`. The contract line was fixed; the directory
  stays excluded, for the same reason `docs/adrs/` is.

## Open questions

* Extensionless references under inner folder names (`drawing/earlyBoot`, a module specifier) are
  not checked at all. Resolving them by stem would catch stale module names, but coloring page ids
  and GitHub actions have the same shape.
* The step 4 hunt depends on a commit naming the skill to find its window. If runs happen under
  other names, the 30-day fallback applies.
