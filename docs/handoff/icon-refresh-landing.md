## Decisions made (and why)

**Seven icons are new files, not repaints.** Verified by grep, not assumed — the obvious name to
reuse is in each case still needed by a different control:

| New file            | Why the existing name can't be repainted                                           |
| ------------------- | ---------------------------------------------------------------------------------- |
| `appearance.svg`    | `theme-auto` is the System option in the theme picker and AppearanceSection inline |
| `sound.svg`         | `volume-on` is half of SoundSection's on/off ToggleRow pair with `volume-off`      |
| `save-picture.svg`  | `download` is AiImageResult's download button and the AiFeatureToggles row         |
| `controls.svg`      | `dashboard-customize` is used inline by CompactShell and ControlsSection           |
| `feedback.svg`      | `more-horiz` is the admin console's InviteLedger row menu                          |
| `whats-new.svg`     | What's New was only borrowing `magic-brush`, which stays the drawing tool          |
| `parent-center.svg` | Brand new; the filename is a guess at what the unbuilt section will call it        |

`setup.svg` is a rename of `pin.svg` rather than a new file — `pin` has no other consumer, so it
retires after the swap.

`camera.svg` and `magic-brush.svg` are **replaced in place**; every consumer wants the new drawing.

**`ControlsSection.svelte` needs no edit.** The previous handoff listed "point ControlsSection at
the new camera" as a step. It is already `icon: 'camera'` at
`web/src/lib/components/settings/ControlsSection.svelte:84`, and since `camera.svg` is replaced
under its own name, the swap is automatic. Do not go looking for a change to make here.

**Tracing parameters were settled on the first icon and never changed:** white → alpha at tolerance
0.05, `gap_filler.enabled=false`, `shape_stacking=stacked`, `group_by=none`, `max_colors=0`.
Squaring the viewBox and un-grouping were done offline (pure serialization, verified
pixel-identical) rather than by re-spending credits.

**Rejected:** re-enabling the gap filler to remove interior alpha bleed (costs a credit per icon and
reintroduces blended colors), and stroking each shape in its own fill to force overlaps (clears the
artifact at one raster size, worsens another). The bleed is invisible at button sizes on both
grounds — checked by eye at 44 and 128 px.

## Unverified assumptions

* **`Icon.svelte.test.ts` will demand all thirteen in `COLOR_ICONS`.** The chroma classifier decides
  what counts as colorful; every one of these is full-color art, so all thirteen almost certainly
  need registering. Not run, because no file has been copied yet.
* **`parent-center.svg` will trip `icon-orphans.test.ts`** since nothing imports it. The guard's
  behaviour on a deliberately unused icon has not been checked — it may need an allowlist entry.

  `web/src/lib/components/icon-names.d.ts` is its output (it currently lists `'pin'` at line 43).
  Regeneration after the rename has not been run.
* **No icon has been rendered inside the running app.** Everything so far is standalone rendering.
* **`sound.svg` vs `volume-on`/`volume-off` pairing** — the new sound icon is for the *nav row*, and
  the on/off ToggleRow pair is untouched. Confirm SoundSection still reads correctly with two
  different sound icons on screen.

## Risks & next 3 steps

1. **Copy the thirteen files in** — ten from `traced-svg/` (choosing the `controls` variant, below),
   three from `ready-svg/`. Then `npm run gen:icons` to regenerate the `IconName` union.
2. **Register in `COLOR_ICONS`** at `web/src/lib/components/Icon.svelte:16`. `Icon.svelte.test.ts`
   fails any colorful icon that isn't registered, so a miss is caught rather than shipped.
3. **Repoint and prune.** In `web/src/lib/components/settings/sections.ts`, seven of the nine
   entries change — lines 9–16: `theme-auto`→`appearance`, `volume-on`→`sound`,
   `download`→`save-picture`, `dashboard-customize`→`controls`, `pin`→`setup`,
   `magic-brush`→`whats-new`, `more-horiz`→`feedback`. Leave `wand-stars` (AI) and `splotchy`
   (About). Then delete `web/src/lib/icons/pin.svg`, run `npm test`, and screenshot the settings
   modal and `/design` in both themes for the PR.

**Risk:** the repaint-vs-new-file table above. Repainting `theme-auto`, `volume-on`, `download`,
`dashboard-customize` or `more-horiz` would silently change an unrelated control — the theme picker,
the sound toggle, the AI download button, the controls rows, or the admin ledger menu — and no test
would catch it.

**Two decisions the next session should put to the user, not decide alone:**

* **Which `controls` ships.** `controls.svg` is the 4,416-byte trace whose slider tracks arrive
  severed in two (each knob is taller than its track, so the occluded middle isn't in the pixels).
  `controls-primitives.svg` is a hand-authored rebuild — each track a `<rect rx="height/2">`, each
  knob a `<circle>` — at **364 bytes**, costing 0.22 points of fidelity against the source. It is
  geometry authored from measurements, not tracer output, which is why it is a question.
* **Whether five creams collapse to one.** `#F7E8CB`, `#F6E8CE`, `#F1E9D4`, `#F9EACD`, `#F2EBD9`
  span a maximum pairwise distance of 0.059 — the same cream five times. Five hex edits, no
  geometry. The 13 blues are *not* a cleanup: they span 1.124 and are doing different jobs.
