# Android SVG backdrop repair

The brush candidate uses `BackgroundImage` for per-pass Crayon mixing. The Android SVG renderer
retained the screen bitmap while `toDataURL` drew a different bitmap, so an export filter could read
a finished screen scene at another pixel size. The retained bitmap could also have been recycled.
The supported pnpm patch binds each bitmap while its children paint and restores the previous
binding in `finally`. Screen and both PNG export entry points use that same helper. Brush colors,
texture geometry, phase, filters, return opacity and paint order are unchanged.

The lock was generated by pnpm with unchanged supply-chain policies. The first offline attempt
refused missing full registry metadata and remains preserved. The changed-input normal metadata
attempt passed; its emitted lock differs only in the SVG patch registration and importer/snapshot
references. The feature-owned qualifier authenticates the complete effective installed SVG subtree,
including its unchanged nested dependencies, and projects that exact delta back to the inherited
lock and workspace before the existing N1/F1 checks. It rejects source changes, unknown files or
directories, symlinks, foreign paths, patch bypasses and unrelated lock changes. A finite read of
the upstream normal installation found no SVG-local peer bins. The supported patched installation
generated one relative `react-native` bin link. Its literal, exact owned target, bytes, mode and
hash are authenticated separately; nothing is broadly ignored.

The Java files here are source fixtures for positive and rejecting controls. Static package fixtures
are never executed as an installed graph. Source controls and browser results cannot establish
Android filter output. The maintained installed package remains upstream until a supported frozen
installation applies the patch. Actual Java compilation and native exports at different display
pixel densities must still prove the current paint prefix, distinct scenes, Clear, Undo, reopening
and restart. Whole-paper immediate screenshots and original full-RGBA PNG history comparisons keep
their existing strict oracles.

`InkArtwork` owns explicit color-filled texture definitions once per used pigment. Individual `Ink`
children retain their paint order and per-pass Patterns, including four seeded translations and
fixed-tile clipping. Empty paths are omitted after retaining their original shade indices. The
source-render controls compare every RGBA byte against the hash-bound earlier candidate renderer for
repeated colors, mixed backtracking, later solid ink, Magic and live draft ink. They also reject
missing references and changed pigment. Native output must still qualify this shared definition
scope. Full-paper per-pass filters are unchanged.

The prior native Pencil-tip mismatch, native memory threshold and mandatory-observer failures remain
held. This repair makes no memory improvement or framework-selection claim.
