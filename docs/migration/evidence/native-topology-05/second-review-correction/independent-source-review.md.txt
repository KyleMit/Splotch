## Actual finding and correction

Claude's second exact review finding is valid: old live production closure used artifact/version
keys against a historical production-key baseline, so an ordinary shared ms version bump falsely
became a candidate leak. The correlated shipping-import fence also took artifact-exclusive rows'
names, so split versions of a legitimate shared package could become falsely forbidden imports.

* lock-artifacts.mjs:21–37 extracts artifactIdentity without relaxing its existing canonical package
  identity/integrity/source checks. candidateOnlyPackageNames:99–110 compares canonical candidate
  names with canonical current production names, retaining only genuinely candidate-only names.
* topology-policy.mjs:65–84 derives historical baseline production names, then rejects current
  production keys whose canonical name is in the candidate closure and absent from that baseline.
  A shared package's new version is permitted. A new candidate-only name entering production still
  fails, including when its production version differs from the candidate's. The returned artifact
  counts retain their existing exact-key meaning; they are not redefined as name counts.
* check-native-topology.mjs:53–62 keeps candidate archive review before production/import checks and
  passes the new name-only set to the real shipping-import scanner. New candidate/shared archive
  bytes still require the exact reviewed integrity/source/hook row. The artifact-exclusive function
  remains unchanged for exact production-install/exclusive records and their proof consumers.
* production-closure.test.mjs sets up both scoped and unscoped shared-version bumps, checks closure
  acceptance, proves new shared archive bytes fail without their row and pass with it, rejects a
  candidate-only production name at both equal/different versions, and drives the actual shipping
  source scanner with a shared split-version import followed by an illegal candidate-only import.
  Fixture paths and required scanner inputs exist before assertions; the negative cases target the
  intended predicate rather than a missing setup/import. These are source-inspected, unexecuted tests.

No mandatory mitigation call, live/proof separation, archive policy, production witness or source
scanner coverage was weakened by this delta. Static scanner/computed/subprocess limitations remain
those already declared in its scope; this repair does not claim arbitrary runtime reachability.
