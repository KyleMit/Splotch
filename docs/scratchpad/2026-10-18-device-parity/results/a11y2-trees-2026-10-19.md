# A11Y-2 from captured trees: names, roles, states and targets, 2026-10-19

Refs #2978. This record reads the accessibility trees captured by the DS-2, LIFE-1 and SAVE-1
slices, plus the Settings and gate trees explored with them. It runs no protocol of its own. It
verifies and fails no row, because two of A11Y-2's checks are not observable without a screen
reader: focus return and the spoken dialog name. Those stay with PHY-6.

## Sources

* **`iphone-notch`:** XCUITest trees from a fresh iOS 26.5 iPhone 16e simulator. That covers 23 DS-2
  states per arm, the LIFE-1 and SAVE-1 states, the Settings hub, and the Parent Center gate.
* **`android-api36`:** UiAutomator trees of the Settings hub, the drawing screen, and the gate on a
  wiped API 36 emulator.
* **Arms:** `rn` at 00fcc5c78d1031873db1a214301c008daa4bd080 and `ref160` (v1.6.0, source
  6572ed535f243d06e3f7bcaa5986218cac006d86), the slices' artifacts.

## Findings

**Names match on the drawing screen.** Every control the slices drove has the same accessible name
on both arms:

* the six swatches and "Custom Color";
* "Clear drawing", "Expand controls" and "Collapse controls";
* "Undo", "Save screenshot", "Coloring books", "Stroke width" and "Brushes";
* "Pen", "Crayon", "Magic brush" and "Eraser";
* "Size 1" to "Size 5" and "Eraser size 1" to "Eraser size 5";
* "Settings" and "Close".

X59's historical RN names ("More colors", "<colour> paint") do not occur at this head.

**Brush and size options differ in role (B0343).**

* **`ref160`:** each option is a toggle button (iOS `Switch` with the `ToggleButton` trait), with
  value `1` when chosen and `0` otherwise.
* **`rn`:** each option is a plain button. The chosen one carries the `Selected` trait and value
  `1`; the others carry neither.
* **Where it comes from:** `rn` maps `aria-pressed` to the selected state on purpose, because the
  released React Strict DOM renderer omits `aria-pressed` (`src/rsdDrawing/RsdPressable.tsx`).
* **On Android:** `rn`'s chosen option is a `Button` with `selected="true"`. `ref160`'s options are
  `ToggleButton`s that report `checked="false"` whatever is chosen. Its "Lock device rotation"
  toggle does the same while the lock is on. So v1.6.0 exposes no chosen state to UiAutomator at
  all.

On iOS both arms expose which option is chosen. They are announced differently ("selected" against
"on/off"), so the row needs PHY-6's spoken comparison and a reviewed decision before it can pass or
fail.

**`rn` adds expanded state.** "Collapse controls", "Brushes" and "Stroke width" carry the value
`expanded` on `rn` while their drawer or menu is open. `ref160` exposes no expanded state on those
controls.

**Settings hub names join differently.** `rn` names a hub card with a comma between title and
subtitle ("Sound, Volume 50%"); `ref160` uses a space ("Sound Volume 50%"). Every `ref160` card has
a same-named `rn` card; `rn` adds an Accessibility card, which postdates v1.6.0. OV-1 and OV-2 own
those screens.

**`rn` hides the drawing screen behind Settings.** With Settings open, the drawing-screen controls
stay in `rn`'s tree but are marked not visible, and the dialog's title is a static text with the
Header trait.

**Targets (B0345, 48 pt or dp).**

| Control                          | `rn` iOS | `ref160` iOS | `rn` Android | `ref160` Android |
| -------------------------------- | -------- | ------------ | ------------ | ---------------- |
| Drawing-screen controls          | ≥ 48     | ≥ 48         | ≥ 48         | ≥ 48             |
| Settings Close                   | 48 × 49  | 44 × 45      | 48 × 48      | 45 × 45          |
| Hub switches (Night Mode, Sound) | 52 × 49  | 52 × 33      | 52 × 48      | 53 × 34          |
| Gate keypad keys                 | 91 × 47  | 91 × 46      | not read     | not read         |

B0345's source, shipping's `touch-targets.spec.ts`, checks the shared buttons and pickers, the
Settings Close button, the hub switches and the Appearance choices. `rn` meets 48 on every one the
trees reach; `ref160` misses it on Close and the switches.

The gate keypad is outside that spec. Shipping sizes a phone key at 46 px
(`ParentalGateKeypad.svelte`), and `rn` copies that height on purpose:
`src/parentCenter/parentGateMetrics.ts` holds it, and
`tools/tests/native-parent-center-parity.test.mjs` reads it back from shipping. So the keypad's 47
pt is parity with shipping, not an `rn` regression. Whether the parent-facing keypad should meet 48
is a question for shipping, and stays open.

## Not observable here

* **Dialog accessible names (B0341).** `rn` passes the dialog's label to the native `Modal` as
  `accessibilityLabel`, with `aria-labelledby` on web. XCUITest shows no labelled container for it,
  only the "Settings" header, while `ref160`'s WebView exposes "Settings, web dialog". Whether
  VoiceOver announces the name is a PHY-6 check.
* **Focus return after a dialog closes (B0344, B0251, B0281).** Neither XCUITest nor UiAutomator
  exposes screen-reader focus.
* **Hub switch hit edges (B0167, E0699, E0700)** were not driven.
