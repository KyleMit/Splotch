# KEY-1 slice: hardware keyboard on iPad and Android, 2026-10-19

Refs #2978. This is a diagnostic slice of KEY-1 (`../execution-plan.md`), not a KEY-1 run. It found
one `rn` defect, #3031: on an Android phone the grown-up check ignores hardware keys. That fails
B0206 and E0450. It verifies no row.

## What ran

* **`rn`:** Release builds of 00fcc5c78d1031873db1a214301c008daa4bd080, bundle ID
  `art.splotch.migration.probe`: the iOS simulator binary (SHA-256 `a9abc80fd9fc59e5…`) and the APK
  (`f2704d0abeaa0685…`).
* **`ref160`:** the reconstructed v1.6.0 reference, source 6572ed535f243d06e3f7bcaa5986218cac006d86,
  bundle ID `art.splotch.app.baseline.release`: iOS binary `cfbf1deb3b51bb1c…`, APK
  `099f4bf957b9b45c…`.
* **Targets:**
  * `ipad-13`: a fresh 13-inch iPad Pro (M5) simulator, iOS 26.5 (23F77), portrait.
  * `android-api36-tablet`: a wiped Pixel Tablet API 36 emulator, landscape.
  * `android-api36`: the wiped Pixel 7 API 36 emulator of the DS-1 and LIFE-1 slices, portrait. It
    is not a KEY-1 target, and ran first.
* **Key paths:**
  * iOS: Cmd+Z goes through XCUITest's `typeKey` with the Command modifier. Delete, Escape and
    Return go as HID keyboard usages (`mobile: performIoHidEvent`, page 7). `typeKey` sends none of
    those three as UIKit key commands; on the simulator `UIKeyCommand.inputDelete` reads U+0008, the
    input `rn` registers.
  * Android: `adb shell input keyevent`, and `input keycombination` with Ctrl for the undo shortcut.
* **Driver:** the DS-2 slice's runner, recording each step and capturing its settled still and tree.
  Each arm starts from a fresh install. A cleanup after a step's capture closes anything an arm left
  open, so the next step starts from the drawing screen.

**#3031.** On the phone, the answer slots stay empty and the check stays on its problem. A single
digit sent by hand does the same. UiAutomator reports the focus on the modal's shortcut receiver
(`modal-keyboard-scope`), not on the gate's (`parent-gate-keyboard`). The phone opens the check from
the compact Settings hub, the tablet from its sidebar.

**The reference.** v1.6.0's iOS app ignores every hardware key here: X49 and X38 record that.
Shipping's native iOS app still has no key command bridge. On Android, v1.6.0 handles the same keys
through its focused WebView.

**Not judged.** In the tablet runs the Feedback tap opened the wrong section, so the field the step
typed into is not the Feedback field. On the reference phone the capture shows the Settings hub, not
the Feedback section. On the `rn` phone the Feedback field emptied, but the dialog hides the
drawing, so whether the drawing stayed is not shown there. The iPad run, and a repeat by hand with
the ink in view, show it stays.

**v1.6.0 on the emulators.** As in the Android DS-1 slice, the reference draws offset copies of one
driven stroke, and a single undo removes them all.

## Not covered

* `ipad-mini`, and RN web (`rn-web-chromium`).
* Arrow keys in segmented pickers (B0172, E0483), keyboard activation of colours (E0420, E0595), and
  focus return after Escape (B0091, E0355, E0356, E0360). Focus return needs a screen reader or a
  focus probe; neither driver reports it.
* A menu behind a keyboard Settings session (B0107, E0419), the warning keyboard path (B0237,
  E0443), repeated Escape on the success card (E0449), and a footer retarget (E0456).
* The undo cue's sound (B0020, E0503); audio was not captured.
