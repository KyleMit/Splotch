outcomes so the statuses can be applied to `../protocol-mapping.csv`.

## Method

The harness is in `web/` (see `web/README.md`). Each cell drives both arms through the same public
controls on a fresh browser context and returns what each arm showed, stored and fetched.
Observations are in `web/web-1-observations.json`. Two second takes are in
`web/web-1-repeat-observations.json`: the repeat of `sw-update-lifecycle`, and the corrected
`sw-repeat-visit-and-offline`. Captures are 360 px webp files in `web/shots/`.

* **Driver admission (#2921).** The 8 ms stroke driver was admitted on both arms for mouse and
  touch. Three separate strokes left three Undo steps, and the same paths in one contact left one
  (cells `driver-mouse` and `driver-touch`).
* **Settle rule.** Every capture waited for three consecutive byte-identical frames, all at least 1
  s after the last input, sampled every 250 ms (`settle()` in `web/harness.mjs`). Frames taken
  mid-animation are labeled as such.
* **Comparison rule.** A box whose edge is more than 2 px from its counterpart fails, and so does a
  different control set, control order, text or line break. Line breaks are read word by word
  (`readBanner()` in `web/page-probes.mjs`).
* **Profiles.** Desktop 1280x800 (Chrome user agent), Android phone 412x915, iPhone 390x844, iPhone
  Chrome, iPad 820x1180, Android tablet 1024x768, plus landscape variants. Touch profiles drive CDP
  touch events.
* **Environment emulation, applied identically to both arms:**
  * shipping's own standalone `matchMedia` shim (`web/tests/web-back.spec.ts`);
  * a page-visibility shim, because headless Chromium never hides a page;
  * a synthetic `beforeinstallprompt` that records `prompt()` calls;
  * `navigator.connection` shapes;
  * a recorder on `ScreenOrientation.lock`;
  * IndexedDB cleared through CDP `Storage.clearDataForOrigin`, as the shipping vault specs do;
  * for a deploy, a proxy that serves a byte-changed `sw.js` and a newer `version.json`
    (`web/arm-proxy.mjs`).
* **Fixtures.** `/api/*` was answered by a labeled fixture. Coloring book files requested from
  `https://splotch.art/coloring/**` were answered from the head's committed `web/static/coloring`.

## Could not verify

* **Real folder save** (B0306, L0193, X61). Headless Chromium rejects `showDirectoryPicker` with
  `AbortError: The user aborted a request` in both arms. A diagnostic run replaced the picker with
  the origin-private directory: both arms wrote `splotch-YYYY-MM-DD_HH-MM-SS.png` there and
  downloaded nothing. That is not a pass of a real folder choice.
* **Root error boundary** (B0316, B0318, E0325, E0331). There was no fault path that works the same
  in both arms. Failing every not-yet-loaded script before opening Settings left shipping working
  (its chunks were already loaded), while RN showed a "Did not load" dialog.
* **Shipping-only test seams** (E0683, E0685). These need hooks that exist only in shipping's test
  build.
* **Connection policy** (B0286, E0178, X51). With #3014, RN downloads nothing on any connection, so
  the Save-Data, 2g and cellular rule cannot be observed.
* **Hosted-route disposition** (X64). The RN export serves `/privacy`, `/changelog` and `/feedback`
  itself, as in-app pages over the drawing shell. No host combines it with the retained SvelteKit
  routes, so "resolve beside the drawing route" cannot be checked. #3007 records the intended end
  state.
* **Offline boot after a deploy** (E0328). The first take failed on RN; 13 isolated reruns passed.
  It is recorded as a fail under #3027 until a quiet-host repeat settles it.
* **Legacy page cache** (E0640, E0641). RN leaves shipping's legacy `pages` cache in place. This is
  recorded as an accepted cutover-data-loss difference, because `docs/migration/WEB-CONTRACT.md`
  does not require deleting inert caches. The owner should confirm that reading.
