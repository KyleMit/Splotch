# SAVE-1 slice: Save Picture on the iOS simulator, 2026-10-19

Refs #2978. This is a diagnostic slice of SAVE-1 (`../execution-plan.md`), not a SAVE-1 run. It
verifies no requirement row: each row it touches also runs on targets this slice did not cover. It
found no defect in `rn`.

## What ran

* **`rn`:** the RN Release simulator build of 00fcc5c78d1031873db1a214301c008daa4bd080, bundle ID
  `art.splotch.migration.probe`, SHA-256 `a9abc80fd9fc59e5…`.
* **`ref160`:** the reconstructed v1.6.0 reference, source 6572ed535f243d06e3f7bcaa5986218cac006d86,
  bundle ID `art.splotch.app.baseline.release`, SHA-256 `cfbf1deb3b51bb1c…`.
* **Target:** `iphone-notch` (iPhone 16e), iOS 26.5 (23F77), status bar frozen at 9:41. Raised,
  light, portrait.
* **Photos access.** Granted with `xcrun simctl privacy … grant photos-add`, then revoked for the
  last step. A privacy change terminates the app, so each was followed by a relaunch.
* **Driver:** the DS-2 slice's runner, which records each step and captures its settled still and
  tree. Every step settled.

## Steps and outcomes

| Step                                    | Rows  | `rn`                                                         | `ref160`                                                           |
| --------------------------------------- | ----- | ------------------------------------------------------------ | ------------------------------------------------------------------ |
| Save Picture with ink on the page       | T1-14 | Flash, then the polaroid flies to the camera tile            | The same                                                           |
| Three taps on Save, 150 ms apart        | X43   | One flash and one polaroid                                   | The same                                                           |
| Save, then draw a second zigzag at once | X5    | The polaroid flies and the second zigzag draws cleanly       | The polaroid flies; the zigzag gains a straight line along its top |
| Save with Photos access revoked         | T1-14 | "Your picture wasn't saved" with Open Settings and Try again | The polaroid flies as if saved                                     |

* **The denied save.** v1.6.0 predates shipping's save-failure handling: `saveFailureCopy.ts` and
  its banner landed after 6572ed5. `rn` follows current shipping, so this is reference drift.
* **The stray line while saving.** The line appears on `ref160` only. `rn`'s stroke matches the
  input.
* **Timing, not judged.** `rn`'s polaroid holds about 0.4 s longer before it leaves than `ref160`'s.
  Current shipping retuned its motion after v1.6.0, so like the DS-2 slice's durations this needs
  the `web-prod` triage arm before it is judged.
* **Burst count.** With three taps 150 ms apart, both arms flashed once and flew one polaroid. The
  Photos library itself was not read, so the number of written files is unchecked.
