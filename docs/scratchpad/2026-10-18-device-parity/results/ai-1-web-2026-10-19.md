## The fixture

`web/ai-fixture.mjs` answers every hosted AI endpoint either arm calls: shipping on its own origin,
RN web on `https://splotch.art`. Preflights get CORS headers, and each request is recorded:

* method and path;
* whether it went cross-origin, and whether it carried `Origin`;
* which credential headers it carried;
* the upload's content type, image format and size, and multipart part names;
* the reply given.

Pictures are the shipping AI harness's own JPEGs (`web/tests/artifacts/ai-output-*.jpeg`, 1024x1536
and 1536x1024). The report token is the harness's mock token.

| Case                     | Fixture reply                                                                     |
| ------------------------ | --------------------------------------------------------------------------------- |
| success                  | `200 image/jpeg`, `X-Report-Token`, `X-Free-Generations-Remaining: 9`             |
| refusal                  | `422` JSON with `X-Report-Token`                                                  |
| retry, Still not working | `500` JSON, then a picture; or `500` twice                                        |
| timeout                  | the request never answers                                                         |
| 429                      | `429` JSON with `Retry-After: 60`                                                 |
| poll past 240 s          | `202` ticket, then every `/api/generation-result` poll `202` for 260 s            |
| attempt 33               | 33 successive generations, each closed                                            |
| malformed bodies         | bare HTML `502`; `200` with broken JSON; `200 text/html`; `500` with an extra key |
| exhausted mid-run        | `403` `FREE_GRANT_EXHAUSTED`, `remaining: 0`, the server's own body               |
| report                   | `200` with a report ID; `500` then `200`; or never answers                        |

Steps covered: the prompt, the waiting dial, minimize and the polaroid, the result, Download and
auto-save, the picture and refusal reports, the problem report, the Settings deep link (phone hub
and wide shell), the offline AI button and its first paint, the badge before the grant, a reload
mid-run, focus after close, and leftover legacy credentials.

## Method

Observations are in three files. Each is the same cell module run as a separate batch, so the long
cells could overlap:

* `web/ai-1-observations.json`;
* `web/ai-1-extra-observations.json`;
* `web/ai-1-poll-observations.json`.

The Codex review of round 1 found two AI-1 cells whose passes the evidence did not carry. Both were
fixed and rerun, and the second takes replaced the first in `web/ai-1-observations.json`:

* `ai-offline-first-paint` (E0021, B0314) had reloaded offline with no service worker in control and
  captured Chrome's offline page on both arms. It now registers the worker, boots once under its
  control, and requires the shell to load offline before reading the drawer.
* `ai-layout`'s landscape variant had failed on both arms, because a landscape phone shows only the
  compact Settings card. It now enables AI upright and turns the phone before generating.

`web/compare.mjs` now reports a harness error on either arm as a difference. Commit
55d88e308a40bca0bfa299ccb5fc1f02bd107ff1 had withdrawn E0021, B0314 and E0074 to not run, pending
these reruns; the second takes restore them on their own evidence.

The driver admission, settle rule, comparison rule, profiles and external-request guard are the same
as WEB-1. Waiting dials and confetti are captured mid-animation, without settling, and labeled as
such. Picture equality was judged by pixels (`ai-result-pixels`), because the two arms' image
elements have different boxes for the same visible picture: inside the card, 0.90 % (phone) and 0 %
(desktop) of pixels differ by more than 24 of 255.

  the phone profile. In the phone capture, 5.7 % of the palette band's pixels differ by more than 24
  of 255, mostly at edges. No row names the scrim's blur, so no outcome changed.
