# LIFE-1 slice: restart, cold launch and Android Back, 2026-10-19

Refs #2978. This is a diagnostic slice of LIFE-1 (`../execution-plan.md`), not a LIFE-1 run. It
verifies no requirement row: each row it touches also runs on targets this slice did not cover. It
found no defect.

## What ran

* **`rn`:** RN Release builds of 00fcc5c78d1031873db1a214301c008daa4bd080, bundle ID
  `art.splotch.migration.probe`. The iOS simulator binary is the DS-2 slice's (SHA-256
  `a9abc80fd9fc59e5…`); the APK's SHA-256 is `f2704d0abeaa0685…`.
* **`ref160`:** the reconstructed v1.6.0 reference, source 6572ed535f243d06e3f7bcaa5986218cac006d86,
  bundle ID `art.splotch.app.baseline.release`. iOS binary SHA-256 `cfbf1deb3b51bb1c…`, APK
  `099f4bf957b9b45c…`, the DS-1 slice's artifacts.
* **Targets:**
  * `iphone-notch`: the DS-2 slice's iPhone 16e, iOS 26.5 (23F77), status bar frozen at 9:41.
  * `android-api36`: a Pixel 7 API 36 emulator, cold-booted with wiped data and no snapshot. It used
    gesture navigation and SystemUI demo mode.
* **Axes:** Raised, light, portrait.
* **Driver:** the DS-2 slice's runner, recording each step and capturing its settled still and tree.
  Android's first-launch "Viewing full screen" confirmation was dismissed on both arms alike. Every
  step settled.

## iOS: restart and cold launch

Each arm was installed fresh. The choices were then made through public controls: Black, Crayon at
Size 4, the drawer left open, a zigzag drawn, and Sound turned off in Settings. The arm was then
terminated and relaunched twice, the second time with the Eraser held.

| What survives a restart               | Rows                | `rn` | `ref160` |
| ------------------------------------- | ------------------- | ---- | -------- |
| Sound stays off                       | P1                  | Yes  | Yes      |
| Crayon stays the brush                | B0050, B0096, E0512 | Yes  | Yes      |
| The Eraser is not restored; Crayon is | B0050, B0096        | Yes  | Yes      |
| Size 4 stays the width                | B0049               | Yes  | Yes      |
| The drawer stays open                 | E0515, B0104        | Yes  | Yes      |
| The colour returns to Purple          | B0052               | Yes  | Yes      |
| The ink is gone; the page is blank    | P1, B0063           | Yes  | Yes      |

**Cold launch.** Both arms show the system launch transition, then paper.

* `rn` paints the full persisted chrome in one frame: the purple band, the palette, Crayon and the
  open drawer.
* `ref160` first paints its chrome under a white band with the layout shifted, then settles a frame
  later. That is the X58 jump; `rn` does not have it.

The iOS top band coloured from launch is the settled accepted difference.

## Android: system Back

| Back with                             | Rows         | `rn`                                                                                                          | `ref160`                     |
| ------------------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------- | ---------------------------- |
| Settings open                         | B0322, P16   | Settings closes                                                                                               | The app goes to the launcher |
| A Settings section open (Tool Drawer) | B0323        | All of Settings closes                                                                                        | Not reached                  |
| Ink on the page                       | B0322, X63   | "Leave Splotch?" asks: "This drawing stays while Splotch is in the background. It is lost if Splotch closes." | Not reached                  |
| The leave dialog open                 | B0322        | The dialog closes and the ink stays                                                                           | Not reached                  |
| A blank page after relaunch           | B0322, B0325 | The app goes to the background                                                                                | Not reached                  |

`ref160` predates shipping's Android Back handling. `web/src/lib/boot/systemBack.ts` and its plugin
landed on 2026-09-13, after v1.6.0, so the reference cannot compare these rows. `rn` behaves as each
row describes. X63's copy is true on `rn` because restoration is removed, which is the settled
removal of restoration.
