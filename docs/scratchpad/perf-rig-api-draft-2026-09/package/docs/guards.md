# Guards and verdicts

Every capture carries a trust ledger: one entry per guard and verdict, each `verified`, `failed`,
`unrecorded` (should have run on this transport and did not; read as failed) or `not-applicable`
(does not apply to this transport, page delivery or scenario kind by the package's table, never by
omission). Guards run before measurement and refuse with exit 2; verdicts run after and fail with
exit 1 once the artifact is written. The order below is the order they run. Applicability keys on
three facts the plan resolves: the transport pairing, `resolvePageDelivery(target, kind)`, and the
scenario kind.

## Verdicts (after measurement)

A verdict applies by scenario kind as well as by transport: a capture that took no strokes (a
`session` with no beats, a `first-show`) records the drawing verdicts as `not-applicable`, never as
failed, and a discrete-action sweep proves its input through activation evidence rather than pointer
moves.
