# RN drawing-app regression plan

Candidate: b236d639160459eecd60900926c759af5d4ae080. Prepared 2026-10-21 UTC.

Scope: `/` in RN web and the dedicated API 36 Android phone emulator. No product edits, real AI
calls, real credentials, information routes, GitHub writes, or iOS operations. Web fixture drivers
block network outside loopback; AI requests are answered by the existing AI-1 fixture. Native
coloring may use its public asset host; native AI remains off. Compare uncertain behavior with
shipping web built from this checkout, labeling that source rather than claiming deployed-version
equivalence. A better intentional RN decision takes precedence.

## Execution and evidence

Run each web case in Chromium, WebKit and Firefox, sequentially at phone 390×844 touch, tablet
820×1180 touch, desktop 1280×800 mouse. Firefox lacks Playwright mobile emulation; retain the
viewport and touch capability where supported and record limitations. Chromium uses trusted CDP
touch for multi-contact drawing. WebKit/Firefox multi-contact synthetic PointerEvents exercise
handlers only and cannot establish trusted touch fidelity; mark those subcases blocked. One browser
and one dedicated emulator only. Servers use unused ports 6100–6199 and are stopped at phase
boundaries. Browser input waits for hydrated controls, landed dialogs and durable selected state.
Driver admission: three separate strokes must produce three Undo units; the same paths joined into
one contact must produce one.

Fresh browser context for independent cases; no settings seeding except explicitly named
platform-event fixtures. Default light/system appearance, standard font, Raised controls, AI off.
For dependent sequences, record the earlier case ID as the precondition. Capture screenshots and
relevant accessible state/request logs in `evidence/`; keep raw failures. A pass describes only
assertions actually observed. A screenshot alone does not establish sound, haptics, screen-reader
speech, persisted bytes or physical input fidelity. Report reproducible defects only after two
independent attempts, with comparison and known-issue triage. An automated test listed below
supplies existing partial coverage; it is not evidence that this campaign ran the case. `Manual`
means the full public flow is not automated by that listed test.

The original parity protocols DS-1/2/3, OV-1/2, A11Y-1/2, KEY-1, SAVE-1, COL-1, LIFE-1, AI-1 and
WEB-1 in `docs/scratchpad/2026-10-18-device-parity/execution-plan.md` supply extended axes and
expectations. This bounded campaign records its own diagnostic results; it does not promote those
protocols to final parity acceptance.
