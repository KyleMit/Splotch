# RN E2E dispositions, group A (`a11y` to `engine-pointer-recovery`)

Issue #3154, part of epic #3148. ADR-0182 sets the rule: port a SvelteKit E2E spec when it tests
behaviour the React Native app has and nothing else covers it; otherwise delete it and record why,
as "covered by X" or "Svelte-only: why". Each of the 41 specs below was decided on its own, test by
test, against the RN export (`npm run build:site`, served as the Netlify deploy serves it).

A spec that is partly ported has its ported tests in `e2e/specs/` and says what became of the rest.
"RN gap" marks behaviour the shipping SvelteKit app had and the RN export lacks or gets wrong; each
is parked as a product question and not ported as a failing spec.

Coverage cited as "covered by" was read, not assumed: the named file holds a test for the behaviour.
`web/src/lib/drawing/strokeMath.test.ts` is shared framework-free logic the RN app still imports,
and it moves with #3163.

## RN gaps parked as questions

Each is observed in the export, not inferred. None is ported as a failing spec.

1. **First frame at 1366×1024** differs from the settled screen in about 6,600 pixels (light) and
   6,100 (dark): the Black and Custom Color swatches sit 3 px off. ADR-0180 records 0 pixels at
   every variant viewport. `first-frame.spec.ts` caps the screen at 7,000 pixels and fails when the
   drift stops.
2. **`/design`** carries a scrollable scroll-cue specimen with no focusable content (axe
   `scrollable-region-focusable`, serious). Shipping's styleguide passed the same scan.
3. **Admin sign-in placeholder** reads 3.4:1 on the dark paper; shipping re-inked every placeholder
   to clear 4.5:1. The light paper passes and is held.
4. **After a failed refusal report** focus lands on Close, not on the retry button.
5. **Clear within about 100 ms of Save** is dropped; the page returns when the save's flight ends. A
   press a moment later clears normally, and the saved picture is whole either way.
