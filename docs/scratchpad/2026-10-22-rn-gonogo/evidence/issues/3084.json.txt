    "body": "## Idea (backlog; not part of the RN migration)\n\nOffload native builds from the developer Mac to GitHub Actions. The repo is public, so runners are free (macOS runners have a concurrency cap).\n\n* **Trigger.** A `workflow_dispatch` workflow (`probe-build`) takes a `ref`, run with `gh workflow run probe-build -f ref=<branch>`. A small `tools/` script then runs `gh run download` and installs the result.\n* **Android.**\n  * An Ubuntu runner builds the probe APK, caching Gradle, the NDK and Metro.\n  * Signing uses a committed throwaway probe keystore (not secret, like Android's public debug key), so CI and local builds share a key and `adb install -r` upgrades in place.\n* **iOS simulator.** A macOS runner builds an unsigned simulator `.app`; install it with `simctl`.\n* **iOS physical device.** CI builds with `CODE_SIGNING_ALLOWED=NO`, and the Mac re-signs the downloaded `.app` locally with the existing identity and profile. No signing material goes into GitHub secrets.\n\n## Why\n\n* Parallel agent sessions each want builds, and two local Gradle or xcodebuild runs at once roughly double both.\n* CI builds would let sessions keep working while a build runs elsewhere.\n\n## Trade-offs\n\n* End-to-end latency is worse than a local build (queue, cold-ish runner, a ~50 MB download). That suits throughput across sessions, not tight diagnose-rebuild loops.\n* CI builds must match the local build config (env flags such as the perf probe, the `Podfile.lock` step), via a shared build script or a drift guard.\n\nLower priority than skipping native builds for JS-only changes (the companion issue).\n",
