Neither is a parent of this issue.\n\n## Why\n\nOn 2026-10-20 the owner hand-tested the React Native app on a Galaxy and an iPad and found about 14 bugs that CI and the agent campaigns had missed (#3062 to #3079). Every build and device check runs on one Mac with one Galaxy and one iPad, so builds, perf captures and device runs queue behind each other. This issue asks how rented compute and devices could:\n\n1. remove that bottleneck;\n2. find bugs before the owner does.\n\nThis is a starting point for investigation, not a decision. Prices quoted below are rough and need checking.\n\n## Why the bugs slipped through\n\n* **Tests ran against fakes that behave unlike the platform.** All the AI and settings-save bugs passed CI:\n  * Node's `Blob` accepts bytes where React Native's rejects them;\n  * mocked `File.write` was synchronous where Expo SDK 58's is async;\n  * the PNG fixtures lacked the provider's C2PA chunk;\n  * the iOS keychain `nil` → `undefined` interop and `/private/var` paths exist only on a device.\n* **Parity checks compare still frames of chosen states.** They miss motion (the Undo fly-away, the Settings dim flash, the coachmark ghost) and sequences, such as a swatch tap followed at once by a stroke.\n* **Performance runs use clean, single-finger synthetic input.** There are no palms, mid-flight re-grabs, taps during a fling, or strokes 100 ms after a colour change.\n* **One configuration per device.** Font scale, keyboard-over-dialog, landscape and edge-to-edge were never varied.\n* **Some bugs are judgement calls.** Spacing and \"barely visible\" fail no check.\n* **AI was never run end to end on a device.** Spend and credential gates kept it out until the owner asked.\n\n## How the code splits by platform\n\nThese figures cover the React Native app in `experiments/native-architecture`, by lines, excluding tests and type declarations:\n\n| Category | Lines | Share |\n| --- | ---: | ---: |\n| Shared (no platform variant) | 57,285 | 81.8% |\n| Web only (`*.web.ts(x)` and their counterparts) | 6,526 | 9.3% |\n| Native only, both phones (`*.native.ts`, files a `.web` sibling replaces) | 893 | 1.3% |\n| iOS only (Swift and Objective-C) | 2,741 | 3.9% |\n| Android only (Kotlin) | 2,571 | 3.7% |\n\n**What that means for coverage:**\n\n* Android-only regression testing would have caught about 12 of the 14 bugs: shared logic runs the same TypeScript on the same Hermes engine.\n* It misses the iOS native layer and bridge (#3068 and #3069 were invisible on Android). It also misses platform behaviour that differs in shared code: iPad size and landscape layout, the keyboard, touch and gesture semantics, fonts, Skia on Metal, and animation feel.\n* So a shared-code fix should be reproduced before, and verified after, on all three targets: Android, iOS and the RN web build. Until now fixes were verified only where they were reported.\n\n## What Codex Cloud can and can't do\n\n* **Can:** run the tests, the RN web export and Playwright. That makes it the \"web environment\" at no extra cost.\n* **Can't:** run an iOS simulator, which needs macOS, or a usable Android emulator, which needs KVM and is too slow without it. `docs/CLOUD/Codex.md` also keeps native toolchains out of that environment.\n* **Prompt drafted in the thread.** A Codex Cloud prompt covers the parts it can do:\n  * a fake-versus-platform audit of the test doubles;\n  * sequence and timing tests in the mounted RSD tier;\n  * a font-scale, dark-mode and landscape layout matrix on the RN web export;\n  * an animation-divergence report against shipping.\n\n## Option: one rented build machine per target\n\nEach target gets the cheapest environment that can build and test it, so nothing contends:\n\n| Target | Fit | Rough cost |\n| --- | --- | --- |\n| Web | Codex Cloud | Included |\n| Android | Linux dedicated server with KVM (e.g. Hetzner, or AWS `.metal`, or GCP with nested virtualization) | About €40–60/month |\n| iOS | Dedicated Apple-silicon Mac (Scaleway Mac mini; EC2 Mac `mac2`/`mac2-m2pro`; MacStadium) | About €75–150/month at Scaleway; EC2 Mac is far more, with a 24-hour minimum |\n\nPick bare metal or a dedicated machine, because the Android emulator needs hardware virtualization. A single Mac could host both iOS and Android, but splitting them avoids build contention.\n\n**Setup over SSH.** An agent (Codex or Claude) can do almost all of the configuration:\n\n* toolchains: Node at the repo's pin, pnpm via corepack, the JDK, the Android SDK and images, CocoaPods;\n* clone, install, build, boot emulators and simulators, and register runners.\n\nThe owner still has to handle:\n\n* accounts and payment, and adding SSH keys;\n* sudo, or run the few sudo steps themselves;\n* the Xcode download (Apple ID) and its license acceptance;\n* Android SDK license acceptance;\n* the GitHub runner registration token;\n* the Codex or Claude login on each box.\n\nTwo more conditions:\n\n* Local Codex needs network access allowed to use `ssh`.\n* Commit the setup as a script, so a box can be rebuilt in one command.\n\n**Where the agent runs.** It's standard to run the agent on the remote machine, not to tunnel each command over SSH from the laptop. The thinking happens on the vendor's servers either way, so the laptop isn't loaded. Tunnelling only adds per-command latency and dies when the laptop sleeps. The Claude desktop app's SSH sessions run the agent remotely while you steer it locally.\n\n**Credential hygiene on rented boxes.** Treat each box as disposable:\n\n* a dedicated, spend-limited Claude or Codex credential for that box alone;\n* a fine-grained GitHub token scoped to this repo, or only a runner token;\n* only the probe's debug keystore, with no store signing and no Apple Developer credentials (simulators need no signing);\n* revoke and rebuild if in doubt.\n\n## Coordination patterns discussed\n\n1. **Fix locally, verify on all three.**\n   * A local session pushes a branch, pins the SHA, and dispatches three remote sessions. Each builds that SHA, reproduces the bug, verifies the fix, and returns a fixed-shape verdict: target, SHA, build, checks, and evidence paths.\n   * The local session checks the evidence and owns the fix.\n   * The cheaper routine version uses self-hosted GitHub runners on each machine. A push triggers web, Android and iOS checks automatically, and agents are dispatched only to investigate a failure. This is #3084's idea on owned hardware.\n2. **Regression plus exploration.**\n   * Runners run scripted regression checks.\n   * Agent sessions run exploratory charters rather than pure random input, which mostly finds crashes (`tools/device-parity/run-monkey-seed.mjs` already covers that). Example charters:\n     * colour changes plus fast drawing;\n     * every Settings control at 200% text, then relaunch and read back;\n     * interrupt everything (re-grab Clear, tap during scrolls and saves, rotate mid-dialog);\n     * every animation against shipping.\n   * Each finding needs a SHA, device, repro steps and video, and must reproduce twice.\n   * Findings are deduplicated across platforms, with shipping as the reference.\n   * Each run has a time and spend limit.\n   * Every confirmed bug becomes a scripted regression check.\n3. **Parallel performance candidates.**\n   * The Android box tries about 10 candidate fixes on branches from one base and returns the best one or two. The other targets check those finalists for regressions.\n   * A platform fork (`.ios.ts`/`.android.ts`) is acceptable when it's measured on real devices, small, and tested on its own.\n   * **Caveat:** emulators and simulators don't predict real frame timing. Use them to rank candidates by work counts (the perf probe's commits, records, flushes and samples), by same-machine JS cost, and by correctness under load. Then judge the finalist with one capture on the physical rig.\n\n## Option: real devices in the cloud\n\n| Service | Devices | Use | Rough cost |\n| --- | --- | --- | --- |\n| AWS Device Farm | Android and iOS, including iPads | Appium runs and live sessions; private devices available | About $0.17 per device-minute, or monthly unmetered |\n| Firebase Test Lab | Android, some iOS | Automated runs only (instrumentation, Robo) | About $5 per physical device-hour |\n| BrowserStack App Live / App Automate | Wide catalogue, including iPad Pro and Galaxy | Live and Appium, with automatic iOS re-signing | From about $200/month per parallel device |\n| Sauce Labs, LambdaTest | Similar | Live and Appium | Similar |\n| Samsung Remote Test Lab | Galaxy only | Live remote control | Free, credit-based |\n\n* **Good for:** real-device functional and regression breadth, and per-PR smoke tests on a device like ours. Appium matches the `tools/device-parity` tooling.\n* **Weak for:**\n  * Performance: devices are shared and in an unknown thermal state.\n  * Raw `adb`/`uinput` input such as palms and injected multi-touch: usually unavailable.\n  * iOS signing: needs re-signing setup.\n  * Agent-driven sessions: slow.\n* **Alternative:** a home device lab. An always-on small Mac at home with a dedicated test Galaxy and iPad, reachable over SSH, keeps full `adb`/`uinput` access and stable performance, and frees the owner's own devices and desk.\n\n## Possible combined setup, to evaluate\n\n* **Codex Cloud:** web tests and layout matrices.\n* **Rented Linux and KVM box:** Android builds, emulators and candidate comparisons.\n* **Rented Mac:** iOS builds and simulators.\n* **Self-hosted runners on both:** automatic three-target checks per PR.\n* **Device farm:** real-device regression breadth.\n* **Home device lab or the owner's devices:** performance and touch-fidelity sign-off.\n\n## Questions to answer\n\n* Current prices and minimums for each option. Is a monthly box or an hourly one cheaper at our usage?\n* How much build pressure is left once #3083's JS-only bundle swap lands? The thread's suggestion was the Android KVM box plus self-hosted runner first, then the Mac.\n\n## Done when\n\n* Each option is priced and tried far enough to confirm it can build and run this app.\n* A recommended setup is chosen and recorded, as an ADR if the decision warrants one.\n* Follow-up issues exist for the pieces chosen.\n",
