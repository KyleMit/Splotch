**Credential-continuity verdict: an RN build installed over shipping would NOT find the parent's
saved key or access code on iOS, Android or web.** Even with an identical app id, iOS queries
`service=art.splotch.ai-credentials-v1, account=gemini-api-key`, but shipping wrote
`no service, account=capacitor-storage_gemini-api-key`. Android reads a different file under a
different Keystore alias. Note that the RN probe also ships under `art.splotch.migration.probe`
today (android/app/build.gradle:30-32, pbxproj PRODUCT_BUNDLE_IDENTIFIER), not `art.splotch.app`.
The iOS shipping items also outlive the upgrade as orphans: RN "Forget" never deletes
`capacitor-storage_*` items (iOS can keep Keychain items after deletion). Free-generation identity
carries over on native only with the same Team ID / signing key. Every AI preference (on/off,
customization, auto-save, gate modes) resets because RN cannot read WebView localStorage.

## 4. Concrete differences

* **D1 [H] AI stops working permanently after 32 generations (RN only).** Every run creates a
  durable attempt: iOS `SplotchAIJournal.swift:737` `checked(all.count < maxAttempts)` with
  `maxAttempts = 32` (:25), Android `SplotchAIJournal.kt:737`, web
  `platform/aiStorageRecords.web.ts:23,67` (`MAX_AI_STORAGE_ATTEMPTS = 32`, plus 128 MB). There is
  no attempt eviction anywhere: Swift `unlink` only prunes revisions (:347) and pending files; no
  delete in Kotlin or JS storage. Attempt 33 throws at `persistPrepared`, and
  `generationController.ts:316-330` shows "AI storage did not confirm the save. Nothing was sent."
  Shipping persists nothing. Needs a device or unit test to confirm.
* **D2 [H] Saved credentials are not carried over** (see §2 verdict). Shipping
  `secureStorage.ts:35-36,258-279` with the plugin prefix `capacitor-storage_`; RN
  `iOS:SplotchAIEnvironment.swift:21,29-32`, `AND:SplotchAIEnvironment.kt:37,41-44`,
  `platform/aiVaultRecords.web.ts:3`. The legacy plaintext migration
  (`secureCredentialCoordinator.ts:120-141`) and retired-key purge (`state/aiKey.ts:49-61`) have no
  RN equivalent.
* **D3 [H] Timeouts and unparseable failures lock AI for up to 20 min.** RN `transport.ts:137-142`
  throws on a non-JSON body, and `:312-318` turns any throw or the 27 s deadline into `unknown`.
  `generationController.ts:173-182` persists phase `unknown`; `uiState.ts:110` shows the "Still not
  working" card; `aiCanGenerate`/`unresolved()` block new runs until JOB_TTL (20 min); after a
  relaunch `session.ts:356-359` turns `sent` into `unknown` too. Shipping: `aiImage.ts:264-275`
  (timeout => retry card), `aiImageResponse.ts:90` (a bare 502 is an error the child can retry right
  away), covered by `failure-paths.spec.ts:108-152`.
* **D4 [H] Slow generation never resolves.** Shipping `aiGenerationPoll.ts:29-36,116` turns 240 s
  into a 504 retry card. RN `generationController.ts:367-373` only sets a message (not rendered in
  the product card) and stops polling; `uiState.ts:110` keeps `generating` while `jobId` is set, so
  the dial sits in overrun until the child minimizes and restores.
* **D5 [H] Picture/refusal reports from RN native are likely CSRF-blocked.** RN sends
  `multipart/form-data` (`reportContract.ts:123`) through `platform/ai.ts:107-122`, which adds no
  Origin header. SvelteKit 2.70.3 `respond.js:82-89` forbids form POSTs whose Origin is missing or
  untrusted; `web/svelte.config.js:54` trusts only `https://localhost` and `capacitor://localhost`,
  which the shipping WebView sends. The 403 `{message}` body then fails RN's strict parse, so the
  report is `unknown` and never retryable (D6). Verify against production.
* **D6 [M] A failed report cannot be retried.** RN `reportTransport.ts:82-85` maps a 5xx or timeout
  to `unknown`, and `reportOwner.ts:350-375` keeps `context.used = true` ("will not be sent again
  automatically"). Shipping `AiImageReport.svelte:153-170,174-180` shows the error with a "Try
  again" that re-confirms (ai-report "times out into the retry state").
* **D7 [H] AI button not hidden offline.** Shipping `actionButtonLayout.ts:131-133`
  (`aiImageEnabled && networkState.online`; native uses @capacitor/network plus the persisted
  `splotch-last-network-online`). RN `RsdActionsPanel.tsx:231` checks `aiEnabled` only; there is no
  connectivity source at all. Offline, the drawer keeps one extra slot and the wand reads "AI image
  unavailable".
* **D8 [M] Free badge on cold start.** Shipping seeds from `splotch-free-generation-badge-hint`
  (`freeGenerations.svelte.ts:19-28,138-150`; `AiImageButton.svelte:123-129`), so the badge is right
  at boot or hidden after 'unavailable'. RN `uiState.ts:173-176` uses `state?.remaining ?? 10`, so
  it flashes "10" on every launch until `inspect()` answers.
* **D9 [M] Upload differs.** RN uploads a 1x paper-size PNG (`PictureCapture.tsx:16-18,35-37`;
  `prepare.ts:8-33` asserts the 1x size; `generationController.ts:308` Content-Type `image/png`).
  Shipping uploads the export at `max(devicePixelRatio, 2)` (`drawing/exportScale.ts:3-7`,
  `aiImage.ts:53`) re-encoded to WebP q0.85 where possible (`aiUploadEncoding.ts:1,24-52`; Android
  WebView yes, iOS falls back to PNG). The AI input is 4-9x fewer pixels on RN. The same 1x PNG is
  RN's report `drawing` (`reportOwner.ts:102-132`) and auto-saved drawing
  (`ai/aiAutoSave.ts:33-39`); shipping uses the >=2x PNG (`aiImage.ts:262`, `AiImageReport.svelte`
  drawingUrl = previewUrl).
* **D10 [M] Try again uses the current drawing, not the failed one.** Shipping `retryAiImage`
  resends `aiGenerationState.drawing` (`aiImage.ts:282-294`). RN `generationFlow.ts:153-158` ->
  `run()` -> `prepare()` captures the canvas as it is now (the child may have drawn more while
  minimized), and saves another original.
* **D11 [M] Repeated-failure counter never resets on close.** Shipping `closeAiResult` zeroes
  `consecutiveFailures` (`aiGeneration.svelte.ts:211`). RN resets `failures` only on image or safety
  (`generationController.ts:144,199`), not in `close()`/`dismiss()` (`session.ts:451-466`,
  `generationFlow.ts:122-129`). After two failures in a session, every later first failure shows
  "Still not working" with no Try again.
* **D12 [M] Throttling (429).** Shipping shows the Try again card (`aiImage.ts:109-117`). RN
  `transport.ts:229-237` keeps `retryAt`; Try again is silently refused (`generateAuthorized`
  retryAt check, `generationController.ts:241`), flips to the 'rest' card (`uiState.ts:98`), and the
  wand opens straight to the 'rest' card while throttled (`generationFlow.ts:78-87`).
* **D13 [M] Backgrounding or opening Parent Center closes the AI card.** RN
  `useDrawingProduct.ts:191-197,240-245` calls `ai.close()`. The waiting polaroid needs
  `open && minimized` (`RsdPaperSlot.tsx:52`), so it vanishes, and the next wand tap re-asks the
  gate (`session.ts:451-466` clears parentProof). Shipping keeps the polaroid and restores it
  gate-free (`AiImageButton.svelte:64-67`).
* **D14 [M] RN-only recovery after app kill or close.** `generationFlow.ts:66-110` reopens a pending
  run or any undismissed finished picture "however long ago" on the next wand tap (dismissal stored
  in `Documents/splotch-ai-dismissed-result.txt`). Shipping state is in memory only
  (`aiGeneration.svelte.ts`). Reports on recovered pictures are refused (`reportOwner.ts:283`).
* **D15 [M] No pinch-zoom on the result.** Shipping `AiResultStage.svelte:63` `use:pinchZoom`
  (ai-result "pinch-zooms"). RN `RsdAiResultStage.tsx` has no gesture handling;
  `AiPictureViewport.tsx` is used only by the dead `NativeAiPictureView`.
* **D16 [M] RN-only storage of every original.** `productOwners.ts:56` calls `savePicture(drawing)`
  on every run: native `Documents/splotch-pictures` (`platform/drawingFiles.ts:5-9`,
  iCloud-backed-up Documents), web localStorage `splotch-picture:<id>` up to 8 MB each
  (`drawingFiles.web.ts:27-41`). Nothing prunes it. On web this can exhaust localStorage, after
  which AI prepare fails ("The drawing could not be saved before sending.") and other localStorage
  settings writes may fail. `savedColoringPageIds` also pins coloring pages for these originals.
* **D17 [L] Auto-save switched on after a picture arrived saves it.** RN `useAiAutoSave.ts:76-78`
  effect depends on `enabled`. Shipping decides at commit (`aiImage.ts:261`) and keeps Download
  (`autoSaveCopy.ts` comment).
* **D18 [L] Unreadable stored secret.** Shipping maps AEADBadTag / KeyPermanentlyInvalidated /
  invalidData to `UnreadableSecretError` and allows replacement (`secureStorage.ts:260-274`,
  `secureCredentialCoordinator.ts:52-57`). RN `writeProtected` reads the existing record first
  (`AND:…kt` writeProtected `protectedRecord(name)`, `iOS:…swift:72-76`), so a corrupt record blocks
  every save until Forget. Settings may not offer Forget because `saved` is null after a read
  failure.
* **D19 [L] Style prompt.** Shipping exports the drawing on open and keeps the covers disabled until
  it is ready, with an error state (`AiImagePrompt.svelte:24-53`). RN covers are always live
  (`RsdAiStylePrompt.tsx`); a capture failure surfaces later on the result card.
* **D20 [L] Dial restarts slightly.** `uiState.ts:56-75` changes the run id from `startedAt` to
  `journal.id`; `aiProgress.ts:84-90` restarts from `journal.createdAt`.
* **D21 [L] Web-only RN differences:** different vault DB and installation seed (fresh free grant,
  keys lost); no `requestPersistentStorage` after save (ADR-0128); no chosen-folder auto-save
  caption; absolute `AI_ORIGIN` (`contract.ts:1`, unguarded against `web/securityPolicy.ts:40`).
* **D22 [L] Dead or harness surface still in the tree.** `ai/AiSheet.tsx` shows non-shipping
  `AI_DISCLOSURE`/`AI_WAIT_NOTICE` copy; there is a share sheet (`useAiPictureShare.ts`,
  `platform/aiShare*.ts`) although shipping has no AI share. `AiRecoveryActions.tsx` uses probe
  `Action` buttons, some permanently disabled, and is mounted in the product error card whenever
  `state.recovery` exists.
* **Headers:** equivalent. Both send only Content-Type, `X-Async-Generation: 1`, and one credential
  header (`X-Api-Key` > `X-Access-Token` > `X-Installation-Id`) on generate. Polls send the
  credential header; reports add `X-Report-Token`. Neither sends app version or platform on AI calls
  (only the problem-report body does, guarded). The difference is transport-level: shipping WebView
  requests carry `Origin: capacitor://localhost` / `https://localhost` and a WebView UA, RN native
  sends no Origin (D5).
* **Free-generation identity:** equivalent on native (`state/freeGenerations.svelte.ts:16,32-48` vs
  Swift :64-68 / Kotlin :85-90, same namespace and hash). It differs on web (D21).
* **Invite links:** shipping native ignores them (no appUrlOpen, no applinks); RN native listens via
  `Linking` (`platform/inviteLinks.ts`), but neither app configures associated domains, so this is
  dormant. RN rejects codes with whitespace/control characters (`validCredential`); shipping saves
  any non-empty token.
