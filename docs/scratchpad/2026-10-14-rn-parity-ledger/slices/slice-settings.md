# Slice: Settings dialog, shells, gate, Parent Center, feedback

Pinned at 64a9ca53a. Shipping = `web/src/lib/...`; RN = `experiments/native-architecture/src/...`
(abbreviated `rn/`). Tests: `tests/` = `tools/tests/`, `mig/` = `tools/migration/tests/`. RN
production root is `ProbeApp → RsdDrawingScreen → RsdSettingsRoute → NativeSoundSettingsDialog`
(`rn/rsdDrawing/RsdSettingsDialog.tsx`); `rn/DrawingScreen.tsx` +
`rn/settings/SoundSettingsSheet.tsx` are a legacy surface not reachable from the root.

All RN settings persist in ONE validated JSON record (`rn/settings/soundSettings.ts` +
`soundSettingsCodec.ts`, schema v16): native file `splotch-sound-settings-v1`, web localStorage
`splotch-candidate:sound-v1`. Optional-brush availability lives in a second record
(`splotch-brush-settings-v1`), the coloring mobile-data choice in the offline library's
`policy.json`, the session count in `splotch-settings-activity-sessions.txt` (native) or the
shipping key `splotch-settings-activity-session-count` (web). Nothing reads shipping's `splotch-*`
localStorage / Capacitor Preferences keys, so an upgrading install starts from defaults (only the
web session count carries over).

## 4. Concrete differences

**D1 — Activity dots exist only for What's New (H).** Shipping marks every section with a content
stamp (`components/settings/sections.ts:19-44`; sound/accessibility/ai at '2', whatsnew =
APP_VERSION) and shows a dot on any row whose stamp is unseen once the sixth session is reached
(`state/sectionsSeen.svelte.ts:44-55`), marking seen on drill-in, deep-link landing and the wide
shell's scrollspy (`SettingsModal.svelte:60-86`, `WideShell.svelte:79-82, 172, 243, 305`). RN's
`sectionUnseen` returns true only for `whatsnew` (`rn/rsdDrawing/RsdSettingsHub.tsx:63-65`), the
record keeps only `whatsNewSeen` (`rn/settings/soundSettingsCodec.ts:46-50`), and the wide shell's
`onSeen` ignores every other section (`RsdSettingsDialog.tsx:188-190`). From session 6 a shipping
parent sees dots on every section never opened (`settings-hub.spec.ts:110-113`,
`settings-toc.spec.ts:73-98`); RN shows at most one.

**D2 — Per-session solves leak across policy changes (H, security semantics).** Shipping records a
session solve only when the feature's mode is `session` at solve time and clears it whenever that
feature's mode changes (`state/parentalGate.svelte.ts:310, 519`; unit tests "an every-time solve
does not satisfy a later switch to per-session mode", "changing a policy re-arms a previously solved
per-session gate"). RN adds every solved feature to `sessions` regardless of mode
(`rn/parentCenter/parentGate.ts:202`) and a policy change only calls `gate.invalidate()`
(`rn/product/createDrawingProduct.ts:36-40`), which never clears `sessions` (`resetSessions` has no
caller). Example: solve "Opening Parent Center" under Every time, switch it to Per session, and RN
never asks again this run; shipping asks once more. Conversely RN's policy change bumps
