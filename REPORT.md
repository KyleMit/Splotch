## Finding

Within the permitted evidence, a fully measured transitive Python/macOS loader/native-library
startup byte closure is **an agent source contract, not an explicit requirement in the supplied
human request**. No independent threat/accounting argument establishes that it is necessary before
any original preservation body read. It is genuinely mandatory for the admitted 3587/3603 source's
old qualification schema. It must not be bypassed by filling its flags, weakening its receipts, or
calling unknown costs zero.

A new prospective scope can instead declare the existing Mac and ROOT's host filesystem/crypto
facilities trusted, enforce finite accounting for every controlled preservation input/output and
materialization, and leave ambient platform activity explicitly unknown and outside that narrower
claim. That is a change of qualification boundary, not proof of the old complete-startup promise.
The concrete proposal in FUTURE-DESIGN.md is justified under the stated trusted-host threat model;
it is neither implemented nor ready to execute.

This conclusion is bounded. The supplied human request incorporates CURRENT and selected earlier
receipts; this audit was not authorized to reconstruct those bodies. It cannot establish that no
human ever endorsed a stronger requirement elsewhere, nor identify the first historical author of
the rule. It can identify the rule's concrete provenance and effect in the permitted source.

## Assessment

### 1. Preserve the contract without allowing it to become the only possible task definition

The old startup predicate is real and cannot be waved through. ROOT-TOOLS3587 lines 319–340 require
an external actual qualification receipt before invoking the planner; controller3587 lines 153–201
repeat the requirement. ROOT-RUNBOOK.md lines 26–34 call unknown startup inputs interlocks. The
admitted grant template has an empty startup reference list and complete:false. These explain a
concrete source-level barrier to original reads; this audit does not infer an unobserved runtime
attempt or historical duration.

The strongest conclusion supported is that existing source design makes a stronger proof a
prerequisite. Its existence does not establish that this stronger proof is necessary to satisfy the
human's preservation intent. A prospectively different scope must use a different schema and
consumer; it cannot be emitted as ROOT_COMPLETE_RUNTIME_STARTUP_CLOSURE_3587_V1, set
ROOT_QUALIFIED_ACTUAL_COMPLETE_CLOSURE, or unlock old consumers that require those facts.

### 2. Authenticate controlled code and originals; state where trust stops

Pinned preservation code, direct input manifests, exact original owner/unit/HEAD/index/staged
identity, no-follow handles, complete all-type membership, hardlink/alias rules, streaming body
hashes, deadlines, caps and independent closure directly support preservation. They detect wrong
operands, accidental mutation/rebinding, omitted files/directories, budget overrun and false success
claims. Their provenance remains valuable under a trusted Mac.

A complete host startup closure is a different undertaking. If the threat is a malicious Mac,
loader, interpreter or ROOT host runtime, a receipt produced and checked by that same trusted host
is not independently sufficient to rule it out. If the threat is accidental source mutation,
wrong-root access, hidden candidate imports or uncontrolled dependencies, an explicit narrow
capability boundary and authenticated application sources address it without first certifying all
OS backing images. The inspected evidence supplies no adversarial-host model that selects the
larger undertaking. This is the auditor's reasoning, not a historical human statement.

A useful warning from the source itself is the trust asymmetry: ROOT-RUNBOOK.md lines 18–24 already
requires ROOT's previously qualified filesystem/crypto/process and actual-tool callbacks. The
proposed scope should name those host facilities as its trust base rather than claim to remove all
platform trust through Python image references.

### 3. Startup identity, startup traffic and budget units are different evidence

Hashing an executable or native-library backing file authenticates those file bytes. It does not
by itself measure how many bytes the loader read, faulted, copied or materialized during the actual
launch. Conversely, a bounded channel or a clean exit does not authenticate all implicit loaded
images. The source asks for both kinds of proof but supplies no actual startup collector in the
inspected entrypoint/adapter contract; it requires ROOT to bring one.

ACCOUNTING.md lines 37–50 and plan3587.py lines 67–71 charge repeated full reference occurrences and
actual preparation events. ROOT-ENTRY3587.py.txt lines 1–7 import platform modules before decoding
its controlled payload; lines 15–60 decode and compile authenticated cached sources. Those are
specific application costs to account. The universal host startup byte unit still needs a precise
observer definition before it can be certified. “Complete” boolean fields and path hashes cannot
repair that evidentiary gap.

There is no basis here for saying the old strict requirement is impossible on this Mac, or for
asserting an actual shared-cache size. Neither was measured. The evidence supports refusal under
the old schema until a real collector/ledger exists, and supports a smaller prospective trust
boundary when that is the task's intended proof.

### 4. Exact preservation has three distinct levels; none fills missing history

The human already distinguishes a physical preservation interval from a whole-body rehash (Human
line 51). The source also distinguishes current whole-tree consistency from historical authority:
controller3587.py lines 521–545 reads every regular twice, verifies the known historical source and
index/staged/HEAD, and sets historicalWholeDependencyGitDirectoryEqualityClaimed:false.
core3587.py lines 535–541 show the exact historical-source/index/staged/HEAD comparisons.

A defensible receipt must state separately:

1. Which known historical source/index/staged/identity values match authenticated retained pins.
2. Which complete current original trees were enumerated and hashed twice with stable full tuples,
   all directories, concrete Git/cache bodies, links and hardlink groups.
3. Which protected domains were only left unwritten and observed through retained/current metadata,
   and which historical body/directory baselines are absent.

Two current passes cannot prove an unknown historical dependency body or directory never changed.
A HEAD value alone cannot prove a dirty working tree or staged state. Protected3521/REPORT.md lines
17–30 explicitly preserve these gaps. The seven-domain wholeOriginalProtected/side_authority
promise cannot be replaced silently by an AI-only receipt or by retained 18,510-row subset data.
No saved/held body should be opened merely to make an old flag true without the applicable scope.

### 5. Bounds are conditional; no current fit or zero unknown cost follows

The human's 2,036,273,177 bytes per source+dependency pass excludes Git/metadata (Human line 106).
The later retained case in AI3603/PLAN-INPUT.json is 2,970,134,601 regular bytes per complete pass,
including 927,355,551 Git bytes and 6,505,873 generated bytes across 78,589 regular files. These are
retained case inputs, not this audit's fresh census.

PROSPECTIVE-PLAN.json reserves two passes plus 157,178 EOF-bound bytes: 5,940,426,380 body bytes.
Its retained known metadata/output bound is 490,963,430, aggregate 6,431,389,810; remaining metadata/
output space is 45,907,482 and aggregate space 2,158,544,782. Missing runtime/authority terms mean
fits:false. The narrower design must still preflight a fresh current census, count every
controlled read/materialization/output/probe/receipt occurrence, preserve positive cleanup
reserves, and refuse before original bodies if its bounded terms do not fit. It must not inherit
this retained arithmetic as actual fit or label any unknown term zero.

## Recommendation and limitations

Commission the single prospective trusted-host/controlled-operation design in FUTURE-DESIGN.md,
with a new scope and schema, source admission and meaningful isolated controls before original
execution. Keep the old source packets, admissions, failed controls, receipts and clocks unchanged.
The design supports preserving original bytes and identities under an explicit finite cooperative-
host model; it does not certify the Mac's entire startup traffic or satisfy the old complete-startup
flags. Protected whole-root authority and review-purpose consumer changes remain separate work.

If ROOT decides the old universal startup accounting is essential, the minimum missing deliverable
is an externally trusted pre-exec observer/collector with a precise startup-byte unit, complete
actual image/import/resolution coverage including relevant shared-cache backing identity, bounded
observer costs and same-firstUTC accounting for every launch. It must supply the concrete reference
set and genuine actual return/EOF evidence expected by controller3587.py lines 153–201, then pass
source-bound negative controls and a real preflight inside the existing 32 MiB ROOT startup
suballocation and other fixed caps. Merely adding a Python import list or hashing the Python binary
cannot satisfy that contract. No such implementation, feasible cost or actual qualification was
established by this audit.

The repository ADR index was consulted. ADR-0138 supports keeping evidentiary payloads whole within
an explicitly chosen finite domain, and does not establish a universal OS startup accounting rule.
It concerns capture retention, so it is a principle-level reference, not campaign preservation
execution authority. No ADR or source instruction was changed by this audit.
