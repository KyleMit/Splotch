How a crayon stroke is made

Splotch's crayon is not a picture of a crayon. It is a short list of rules — a paper texture, a threshold, two stroke widths, a seed per pass, and one mixing formula — that together behave like wax. This page adds one rule at a time. Every illustration is the real algorithm, running in your browser as you read.

Brick 0

The whole stroke in one picture

A crayon stroke is the pen's shape, filled with a textured paint instead of a flat colour, laid down in passes, and mixed once with whatever ink is already underneath. Each of those clauses is a brick. Tap one to see what it owns.

Brick 1

The shape is the pen's shape

Before any texture exists, the engine has to know where the finger went. The crayon reuses the pen's answer exactly. Only the paint inside the shape changes later.

Every movement the browser reports becomes an operation (an "op"): a small, self-contained drawing instruction the engine can render, store, and replay. Two kinds of op carry ink. A dot op is a filled circle placed where the finger first touches. A path op is a curve with a line width, drawn with round caps and round joins so segments melt into each other.

The path is not the raw points joined by straight lines. The engine uses midpoint smoothing: each raw sample becomes the control point of a quadratic curve that runs from the midpoint before it to the midpoint after it. The curve therefore passes near, not through, the samples, which removes the polygonal look of hand input. A stroke's ops chain together because each op starts at the midpoint where the previous one stopped.

How many ops per stroke? On the web build the engine records one path op per pointer move, because Safari charges more for a longer path than for an extra op. The native app does the opposite: it merges a frame's moves into one op, capped at eight moves, because that WebView charges per op. The pixels are the same either way; only the op boundaries move.

Brick 2

Paper tooth: a height map that never changes

Real paper is not flat. Its surface has a fine grain of bumps and pits called tooth. Wax sticks to the bumps and skips the pits, which is what makes a crayon mark look broken rather than printed. The crayon needs a model of that grain.

The model is a height field: a 256×256 grid of numbers between 0 and 1, where a high number is a raised bump and a low number is a pit. Each cell of that grid is a texel (a texture pixel). The field is built once from value noise: place random values on a coarse lattice, then blend smoothly between them for every texel in between. One lattice on its own looks like blurry blobs at a single size, so the crayon sums four of them at different cell sizes, called octaves, and weights them so no single frequency dominates.

Two properties matter more than the look. The field is tileable: the lattice wraps at the edge, so the tile repeats with no visible seam and can be used as a repeating fill. And it is deterministic: the random values come from a small pseudo-random generator started from a fixed constant, never from Math.random, so every device builds the identical field and a drawing rebuilds to the identical pixels.

The four octavesA 64×64 corner of each 256×256 tile, magnified 4×. Untick an octave to remove it from the sum.
Lighter is higher. The cell sizes are 6, 4, 3 and 2 texels with weights 0.22, 0.30, 0.30 and 0.18. The body field uses 110-texel cells, which on a 256-texel tile rounds to a 2×2 lattice: a slow drift, not a texture. Brick 3 uses it to wobble density.
Why no coarse octave? A large-cell octave would give the field blotchy, paper-like structure, but a 256-pixel tile with visible blotches repeats visibly across a big fill. The tuning chose fine grain only, so the repeat stays below what the eye picks out. The cost is that a large flood of one colour has no blotch-scale variation; the roads-not-taken section lists this as a known gap.

Brick 3

From height to wax: a threshold with a jittered edge

The height field is grey numbers. Wax is colour with holes in it. The step in between is a single comparison per texel.

A band's coverage is the fraction of texels that should carry wax. The threshold is simply one minus that coverage: a texel whose height is above the threshold gets wax, a texel below it stays a bare pit. The field is normalised to span 0 to 1, but its values cluster around the middle (four noise layers summed tend toward their mean), so a cut at 0.55 covers fewer than 45 percent of the texels. The lab below measures the real share; the name is the knob, the measurement is the truth.

A hard threshold produces hard-edged pits that read as digital dots. The crayon softens the edge without introducing grey: a fixed per-texel dither value nudges the threshold up or down within a narrow band (the edge option, 0.045 either side). Texels near the cut resolve to a stipple of on and off instead of a clean line. The result is still strictly on or off, which brick 4 explains is essential.

Two more fields ride along. Body variation shifts the threshold slowly across the tile using the 110-texel field, so a stroke's density wobbles like uneven hand pressure rather than staying uniform. Shade variation nudges each wax texel's colour a few percent lighter or darker (tall bumps darker, thin patches lighter) so the body is mottled rather than one flat RGB. The shade change touches only the colour channels. The alpha channel stays 0 or 255.

Brick 4

Why the wax is 0 or 1, never in between

The most consequential decision in the crayon is that a texel is either fully opaque wax or fully bare paper. A softer, partly transparent grain looked slightly creamier and was rejected. Here is the arithmetic that rejected it.

Canvas paints with source-over compositing: new paint at alpha a lands on old paint, and the combined alpha is a + a(1 − a) when both are the same paint. For a = 1 that is still 1. For a = 0 it is still 0. For anything in between it grows. A live stroke is made of dozens of overlapping ops (every move op overlaps the one before it by most of its length), so any partial alpha in the grain gets darker each time an op covers it. The texture would then depend on how many ops happened to overlap, which changes with hand speed and with how the stroke is rebuilt after an undo. Binary wax is idempotent: painting the same op again produces the same pixels, so overlap count cannot show.

Mean alpha is averaged over the stroke's interior. The binary row does not move. The soft row fills in with every repeat, which is exactly what a rebuild from a different op count would expose. The one thing binary wax cannot hold still is the anti-aliased silhouette of each band, a ring one pixel wide that no stroking avoids and no eye picks out, so those rings are left out of the average.
The same rule protects the pass buffer. Bricks 8 and 9 accumulate a whole pass on an offscreen buffer before mixing it once. That buffer receives every overlapping op at full opacity, and it only holds still because the wax is binary. The rule was first needed for replay-based undo, which the engine no longer uses, and it stayed because the buffer needs it too.

Brick 5

Two density bands: sparse rim, dense core

A real crayon presses hardest along the middle of its path and crumbles into flecks at the rim. One tile at one coverage cannot do both. Two can.

Each crayon op is painted twice, with the same shape and the same seed but a different density band (the code calls them passes in the options, a name this page reserves for brick 7). The first band strokes the op at its full line width using a sparse tile (coverage 0.45). The second band strokes the same op at 68 percent of the width using a denser tile (coverage 0.63). Widest first, so the dense core lands on top of the sparse rim. Because both bands share the seed, their pits line up on the same paper, and the union reads as one piece of wax with a solid middle and a broken edge.

Brick 6

Seeds: how a second stroke gets denser without getting darker

Press a crayon over its own mark and the mark gets denser, not a different colour. The wax fills pits the first pass missed. The crayon reproduces this with one integer.

The wax tile is turned into a repeating pattern (a CanvasPattern) and the op's shape is filled with it. A pattern has a phase: where in the tile the repeat starts. The crayon anchors that phase to the paper, not to the stroke, so every op in a pass samples the same paper texel at the same paper position. That is what makes a pass read as one continuous piece of wax rather than beads that restart at every op.

Each pass carries a seed, a small integer stored on every op. The seed is hashed into an x and y offset inside the tile, which slides the whole tooth field to a new position on the paper. That slide is the entire difference between two passes. The tile, the colour and the coverage are identical. Because the pits now fall in different paper spots, the second pass fills tooth the first left bare. Coverage rises. And because the wax is opaque and the same RGB, laying it over itself cannot change the hue. That is buildup at constant hue, the behaviour the whole design was chosen for.

What buildup does not model. A real second pass also deposits wax deeper into the same valleys and shifts value a little. The crayon changes only which pits are filled. At toddler scale that reads the same, and it keeps the hue exactly constant, which the deeper model could not.

Brick 7

Passes: when the seed changes

If every stroke had one seed, a back-and-forth scribble in a single gesture would never build up, because every op would share a phase and fill the same pits. Wax does not care whether the crayon lifted. So the unit of phase is not the stroke. It is the pass.

A deposition pass is a run of ops that share one seed. A stroke opens a pass on contact and closes it on lift, but three things can end a pass early. Each end records a flush op, which is the instruction "close the open pass here", and the next op takes a fresh seed.

  • A reversal. The pass tracker measures direction between anchor points at least 0.35 widths apart, so jitter cannot trigger it. A turn sharper than 100° means the tip is heading back over wax it just laid.
  • A re-entry. The tip lands within 0.45 widths of a point laid more than 2.5 widths of arc ago. The trailing arc is excluded because the tip is always near the strip it just painted. Loops and hairpins split here even without a sharp corner.
  • A checkpoint. After 64 pointer moves the pass closes regardless, so a very long scribble never accumulates unbounded pass state. The count is in moves, not ops, so merging moves into ops on native cannot stretch the interval.

All thresholds scale with the line width, so a thin and a thick crayon feel the same. Straight lines, gentle curves, ordinary corners, and hand jitter never split. The tracker's memory is the pass: a split or a checkpoint starts a fresh tracker, so a loop only counts as a re-entry if it closes within 64 moves, and a big lazy circle simply checkpoints. Every seed is stored on its op, so a rebuild reproduces the splits without re-running the tracker.

Brick 8

The glaze: how crossing colours mix

Blue crayon over yellow should look green. Pigments are subtractive: each one filters light, so what you see is the light both let through. Averaging the two RGB values gives grey. The crayon needed a formula that mixes like pigment, and one that leaves same-colour buildup alone.

The formula is two compositing steps applied to a pass as a whole. The first is darken, the per-channel minimum of the new wax S and the ink D already there. Where paper is blank, min with nothing is just S. The second step paints the wax over that again with source-over at alpha 1 − m, where m is the mix strength, 0.55. Together:

out = (1 − m) · S + m · min(S, D) m = 0.55
// blank paper: min(S, nothing) = S, so out = S exactly. Same colour: min(c, c) = c, so out = c exactly.

Two facts fall out of the minimum. Over blank paper the glaze collapses to plain opaque wax, so a first stroke is the exact palette colour. Over the same colour, min(c, c) = c, so redrawing never darkens. That fixed point is what lets the mix ship strong enough to actually see: m could be turned up without muddying buildup. Multiply, the usual subtractive choice, has no such fixed point and darkened every overlap.

Why not m = 1, a pure minimum? Because then blue over yellow would stay green forever, however many times the child draws back over it, and the crayon would appear to refuse to work. The shipped mix walks toward the new colour with each pass: after n passes the old ink contributes only mn.

Mixing labPick an under colour and an over colour.
Averaging is what a plain alpha blend does. Multiply darkens the shared channels and every same-colour overlap. Pure minimum never moves after the first pass. Try under = over to see the fixed point.

Brick 9

Where an open pass lives while the finger is down

The glaze must be applied exactly once per pass, but a child is watching the stroke appear op by op. Something has to hold the growing pass and show the finished mix at the same time. How that is done is the one part of the crayon that differs by platform.

The naive route, glazing every op as it arrives, compounds: a pixel covered by k overlapping ops would be mixed k times and drift toward pure crayon colour in the interior. So the web build keeps a pass buffer, an offscreen canvas where the pass accumulates at full opacity (safe, because the wax is binary), and glazes from the buffer onto the visible ink tile. Two more pieces make that cheap enough for a phone:

  • An under shadow: an offscreen copy of the tile's pixels from before the pass opened. It is read from the tile at most once per invalidation, and the read is deferred to two frames after the finger lifts, because reading a canvas that the browser is compositing forces a GPU pipeline sync. Foreign ink, the eraser, undo, clear, and a closed pass's own wax all invalidate it.
  • A restamp: after each op is painted into the buffer, the tile restores that op's padded rectangle (its bounds plus half the line width plus two pixels of anti-aliasing bleed) from the under shadow, then re-applies the two-step glaze from the buffer over the same rectangle. A pixel's latest restamp is the same function of (buffer, under) that the close-time stamp would have applied once, so live pixels equal committed pixels by construction.
  • A virgin fast path: a pass opening on a blank tile needs no under shadow at all, because the glaze over nothing is just the wax. One plain copy of the rectangle reproduces it byte for byte. This is the common toddler case.

Brick 10

Getting the tiles ready without dropping a frame

Everything above assumes a coloured wax tile exists for the current crayon. Building one is 65,536 texels of threshold and shade arithmetic per band, and the first version did both bands in one go, which cost a 29 to 45 ms frame on an iPad.

Each (colour, band) pair owns a 256×256 canvas. When the crayon is selected or the colour changes, a warm-up job starts on the next animation frame and fills the tile in eight-row chunks until a two-millisecond deadline, then yields and continues on the following frame. A new colour cancels the old job rather than queueing behind it. If a stroke arrives before its tile is finished, the tile is built synchronously as the correctness fallback. The finished pixels are byte-identical either way; only the scheduling differs.

Finished tiles sit in a small least-recently-used cache sized to the palette plus one, so custom colours can never grow canvas memory without bound. A CanvasPattern is bound to the canvas context that created it, so patterns are cached per context and per (colour, band) on top of the tile cache.

Replay a warm-upEight rows per chunk, a few chunks per frame.

Each square is one eight-row chunk. Chunks fill until the frame's two-millisecond budget runs out, then the job waits for the next frame. On a fast desktop the whole tile fits in one frame; on an old tablet it spreads across several, and the drawing loop never notices.

Roads not taken

Popular crayon techniques, and why this one is different

Most of these were built and measured, not just argued about. Each card says what the technique is, what it gets right, and the specific reason it did not ship. Two of them survive inside the shipped brush.

Solid stroke plus random speckle the obvious one

Draw a flat line, then punch holes in it with Math.random noise. It is the first thing everyone tries and it does read as "textured".

Why not: the noise is different every render, so an undo or resize redraws the mark differently (the two halves above are the same stroke rendered twice). The grain reads as digital grit rather than paper, and semi-transparent speckle darkens wherever ops overlap instead of building up at constant hue.

Rejected at the design stage. The deterministic tooth field is the answer to the first problem, binary alpha to the third.

Soft alpha tooth looks creamier

Map the height field to a continuous alpha, so pit rims fade instead of stippling. The swept-passes experiment used exactly this, with nonzero alpha in the valleys so heavy overdraw could eventually fill them.

Why not: brick 4. Fractional alpha accumulates across overlapping ops, so the texture depended on op count and shifted the moment a later stroke was undone. The experiment avoided that by drawing a whole pass as one stroke() call, whose union semantics deposit once, but that forbids per-op live rendering on a tiled canvas.

Partly kept: its pass tracker and its per-pass phase shift are the shipped brick 7, ported with the same thresholds.

Multiply blend for mixing the textbook subtractive

Multiply is what most "pigment" mixing tutorials reach for: out = S × D per channel. It is subtractive and it does turn blue over yellow greenish.

Why not: it darkens every overlap, including same-colour buildup (c × c is darker than c), and it mutes the channels the two colours share, so the mix had to ship weak to avoid mud, too weak to read as green on a phone. Averaging (a plain alpha blend) goes grey, as the middle sample shows.

Rejected for the per-channel minimum, whose fixed point min(c, c) = c allows a strong mix.

Pure minimum, m = 1 cheapest possible

Drop the second glaze step entirely. min(S, D) is idempotent, so it can be painted per op with no buffer, no shadow, and no copies, and it measured at the pen floor on native. A WebGL port could even do it with gl.MIN blending.

Why not: a person drew with it and rejected it immediately. The fixed point cuts both ways: blue drawn back over yellow stays green no matter how many times the child scrubs. The crayon reads as refusing to work. The shipped mix walks toward the new colour precisely because it is not idempotent.

Rejected on appearance. It is why an accumulation surface, or a per-op return step, has to exist at all.

Stamp (dab) brushes Procreate style

Pre-render a textured stamp and place copies along the path at a fixed spacing. This is how most painting apps build textured brushes, and it gives easy per-dab jitter and rotation.

Why not: stamps overlap at every step, so the deposit depends on spacing and speed, which is the overlap problem again with a knob attached. In the GPU spike the stamped renderer was indistinguishable in picture and time from a stroke-shader renderer despite drawing 2.2× the primitives, and five times fewer stamps bought eight percent while visibly changing the pixels. Spacing is not a lever here.

Not pursued. A pattern-filled stroke deposits the tile once per op with no spacing parameter.

A GPU stroke renderer SDF and Ciallo shaders

Render each stroke in WebGL: a signed-distance-field shader or an arc-length-integral shader samples the tooth texture per fragment, and blending does the mixing. Three working architectures were built in a two-day spike.

Why not: GPU cost tracked the render target's area, not the drawn work (a scissor bought exactly nothing), so it did not remove the cost that matters. Under a software rasteriser every WebGL variant was two to three times slower than the 2D canvas, and browsers are withdrawing that fallback, so the CPU crayon could never be retired. Browsers also cap live WebGL contexts well below the tile count.

Rejected as additive complexity: a second renderer to maintain, not a deletion.

Per-stroke composited layers a layer per stroke

Give each crayon stroke its own canvas layer with a soft texture, and composite the layers. This is how a desktop paint program would keep soft grain stable.

Why not: it re-derives undo, eraser, ordering, and export machinery that the single op stream gives for free, and a phone's canvas memory cap is measured in a few hundred megabytes across all live canvases, with allocations failing silently past it.

Rejected twice, in the original design and again when the raster commit was introduced.

Glaze after the lift a 4× native win

Show unmixed opaque wax while drawing and apply the exact glaze two frames after the finger lifts. It measured a fourfold lost-frame improvement on the native app.

Why not: the colour visibly shifts when the stroke lands, bright wax darkening toward what is underneath, and on a device that reads as a glitch rather than as ink drying. Automation measured the win and could not see the cost; a person drawing on the device saw it at once.

Rejected on appearance, with the measurements kept so the headroom is known to be spent.

The open gap. Comparing renders against photos of real crayon, the honest verdict is that colour mixing and mid-stroke pass splitting are the strongest parts, and the missing piece is wax thickness: real deposits vary continuously and value follows thickness, with drag streaks along the stroke direction. The tile model expresses coverage, not quantity. That is a known limitation, not a rejected idea.

Alpha

Band (density band)

Blit

Buildup

Checkpoint
The forced pass close after 64 pointer moves that bounds live pass state.
Composited canvas
A canvas the browser is presenting on screen. Reading its pixels forces the GPU to finish pending work.
Coverage
The fraction of a tile's texels that carry wax; threshold = 1 − coverage.
Darken
A compositing mode that keeps the per-channel minimum of source and destination.
Deterministic
Same inputs, same pixels, on every device and every rebuild. No Math.random, no clock.
Dither band
The narrow range around the threshold where a fixed per-texel jitter decides on or off, so rims stipple instead of aliasing.
Fixed point
An input a function returns unchanged: min(c, c) = c. It is why same-colour overdraw is exact.
Flush op
The recorded instruction that closes an open pass. Later ops take a new seed.
Glaze
The once-per-pass mix with the ink underneath: darken, then the wax back at 1 − m.
Height field
The 256×256 grid of 0 to 1 values that models the paper's bumps and pits.
Idempotent
Doing it again changes nothing. Binary wax painted twice equals binary wax painted once.
Mix strength (m)
How much of the darkened mix survives the second glaze step. 0.55 in production.
Octave
One layer of value noise at one lattice cell size. Four are summed.
Op (operation)
One render instruction: a dot, a path, a flush, or a clear. Stored so a drawing can be rebuilt.
Padded rectangle
An op's bounds plus half its line width plus 2 px of anti-aliasing bleed. The unit of a restamp.
Pass (deposition pass)
A run of ops sharing one seed. Opened on contact, closed on lift, split, or checkpoint.
Pass buffer
The offscreen canvas where an open pass accumulates at full opacity before glazing.
Pass tracker
The pure geometry helper that detects reversals and re-entries on the live polyline.
Pattern
A CanvasPattern: a tile used as a repeating fill, with a transform that sets its phase.
Phase
Where the tile's repeat starts on the paper. The seed sets it; every op in a pass shares it.
Restamp
Restoring an op's rectangle from the under shadow and re-applying the glaze from the buffer.
Seed
A small integer stored on every crayon op, hashed into the pattern phase. New per pass.
Source-over
Normal painting: new pixels over old, weighted by the new alpha.
Texel
One cell of the tooth tile. The tile has 65,536 of them.
Tileable
Repeats edge to edge with no seam, because the noise lattice wraps around.
Tooth
The grain of paper: bumps that take wax and pits that stay bare.
Under shadow
An offscreen copy of the tile from before the pass opened, read at most once per invalidation.
Value noise
Random values on a lattice, smoothly interpolated between lattice points.
