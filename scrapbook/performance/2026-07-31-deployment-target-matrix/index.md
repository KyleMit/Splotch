# Deployment-target performance matrix — 2026-08-21

This deployment-target snapshot combines the campaign evidence declared in `sources.json`.
`6961e50b685d441e88b37d20d3f38a27136572fb` is the measured product commit. Every normalized result
retains its target, mode, commit, and raw artifact; focused action captures, when present, replace
only their declared scenarios within that mode.

The [interactive matrix](./index.html) is the quickest comparison. [`data.json`](./data.json)
contains every normalized drawing run and grouped action result, and
[`sources.json`](./sources.json) records the ordered source campaign.

Regenerate the JSON, Markdown, and HTML after updating the source manifest with:

```sh
npm run gen:performance-matrix -- \
  scrapbook/performance/2026-07-31-deployment-target-matrix/sources.json
```

## Acceptance gates

Drawing passes at paint P95 ≤ 20 ms, P99 ≤ 33 ms, max ≤ 50 ms, and cumulative lost frame time ≤ 1%
of in-contact time. Undo passes at engine P95 ≤ 20 ms, next-frame P95 ≤ 33 ms, and next-frame max ≤
50 ms. A discrete action passes at first-frame P95 ≤ 33.5 ms, post-action frame P95 ≤ 20 ms, and
post-action frame max ≤ 33.5 ms.

## Capture limitations

* All product measurements use 6961e50b685d441e88b37d20d3f38a27136572fb; later commits change only
  performance harnesses and report generation.
* Physical iPad web and native are P1/unmeasured because iOS 26 XCUITest requires a root-owned
  RemoteXPC tunnel that could not be started without an administrator credential.
* iPad simulator native landscape drawing and undo were captured on 2026-08-21 once the runner
  stopped treating an absent in-app rotation lock as an ADR-0090 unavailability: tablets delegate
  orientation to the OS, so device rotation is the only path the product offers there and no
  external rotation or profiling-only preference seam was used. Its two landscape action cells
  remain unmeasured, blocked by a product defect rather than the harness — see issue 1192.
* Android landscape action sweeps were captured on 2026-08-21. A landscape phone renders the compact
  Settings shell, which offers quick toggles and a pointer to portrait instead of the section list,
  so those modes measure that shell under compact-specific labels and each capture records the
  settingsShell it measured. Compare a mode against the same shell; a differing action label set
  between modes is a shell difference, not a regression. Physical Android landscape actions stay
  unmeasured — no physical device was in scope for this pass.
* Resolved campaign-harness P1s: desktop coloring scroll was changed to a trusted wheel path, the
  WebKit coloring-page readiness race was fixed, and Appium 3 borrowed screen/action sessions were
  made W3C-safe with explicit provenance. Exact post-fix retries completed; no product result was
  rerun merely to turn a valid red gate green.
* Two Firefox action waits failed once at different labels and passed their exact retries, so they
  are retained as transient incidents rather than repeated P1s.
* Mac Firefox drawing and all mode-aware Mac undo were captured on 2026-08-21 with the same probe,
  viewports, and gates as the other desktop rows: the frame runner gained Gecko and an undo-response
  measurement, so one pen capture per mode now carries drawing and undo under the same recorded
  orientation and theme. Firefox is Gecko, which no Splotch deployment target ships; read it as the
  third desktop browser a parent might open splotch.art in, never as evidence about WebKit or Blink.
* Desktop captures used exact 1512×982 or 982×1512 CSS viewports at DPR 2. The headed landscape
  browser window exceeded the physical display height at 100% browser zoom, but Playwright retained
  the requested page viewport.
* Simulator, desktop, native-shell, and automated Android results are advisory. Physical iPad web is
  the only Safari-calibrated release-gate transport, and it was unavailable in this campaign.
* Raw perf-profiles are local scratch evidence. The 2026-08-20 captures are no longer on the
  workstation, so their cells are carried forward from the published normalized results and each run
  keeps the raw source path it was captured from; only the 2026-08-21 gap captures are re-readable
  from raw input.
* The 2026-08-21 physical-iPad cells were captured on ce88c8e587ac45847c419e05ef7a79d282bc747a,
  which carries the blank-rotation undo fix; every other cell stays pinned to
  6961e50b685d441e88b37d20d3f38a27136572fb. Those pinned cells were checked rather than assumed: a
  fresh mac-safari landscape-light action sweep at the newer commit matched the pinned result on all
  50 labels within 5 ms, the three blank-rotation labels included, so the pinned rows are not stale
  and were not recaptured. The same labels cost 100-106 ms on the iPad, where resizeCanvas spans a
  4.7 Mpx canvas rather than a 1512x982 desktop viewport - a device-size effect, not a code

## Method

Action sources are applied in manifest order within one target mode. A focused capture replaces only
its declared labels in that mode; all other labels retain their earlier measurement and provenance.
Drawing raw tables and action samples are re-scored with the current metric definitions when this
report is generated; stored derived summaries are not trusted. Physical iPad web remains the
Safari-calibrated release gate. Simulator, desktop, native-shell, and automated Android input are
advisory comparisons.
